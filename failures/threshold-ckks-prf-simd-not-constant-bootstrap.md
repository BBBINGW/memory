## One primary hypothesis / falsifier
[HYPOTHESIS — FALSIFIED for plain SIMD] For FIXED N and straightforward one-scalar-error-coefficient-per-SIMD-slot representation, taking ell full-ring error vectors of length N and merely packing PRF evaluations across BFV SIMD slots can make all outputs fit one O(1) number of ciphertexts and therefore remove ell-dependent bootstrapping cost WITHOUT a new representation/output-expansion mechanism.
[FALSIFIER] Slot capacity: each output ring polynomial has N error coefficients, each standard packed BFV plaintext has at most N scalar slots. For ell distinct independently represented output polynomials, the output scalar count ell*N forces at least ceil(ell*N/N)=ell packed plaintext-ciphertext blocks. The same basic lower bound applies to every intermediate stage that must represent all ell*N scalar states with no entropy expansion/compression; a bit-sliced PRF implementation may require even MORE slots for its state.

## Cheapest decisive test: analytic capacity
[DERIVED] Ring R=Z[X]/(X^N+1); final evaluation-key error e^(j)=Σ_(i=0..N-1) e_i^(j) X^i. ell errors = ell*N scalar coefficients. Standard maximal BFV SIMD packing has N independent slots when plaintext modulus admits complete splitting. Assume a single coefficient per slot, no cross-output packing by bits/digits, no seed compression, and one standard FHE ciphertext per N slots: need ell ciphertexts for ell error polynomials. Numeric concrete example N=2^16=65536, ell=32: 2,097,152 scalar coefficients; at least 32 fully packed BFV outputs. This is an **output ciphertext/slot requirement**, not an information-theoretic proof that every output must be separately bootstrapped. The coefficient encoding of each Ring-LWE polynomial and the BFV SIMD basis are different; additional slot-to-coefficient transformations may be necessary and are NOT free.
[MORE PRECISE PROOF] If the proposal also attempts to derive ell*N statistically independent uniform PRF *output bits* solely via public affine / linear rotations/additions from at most N uniform input symbols, the support of the resulting family has size ≤2^N, whereas independent uniform ell*N bits have 2^(ell*N) possibilities. There is no way to obtain their joint independent-uniform distribution with only such deterministic, non-expanding operations (unless expanding an actual PRG/PRF computationally). Do NOT use this as a formal argument against computational PRG expansion or as an RLWE security attack against correlated error samples.
[EXPERIMENT TYPE] Exact analytical dimension count and support bound, not ciphertext experiment; there is no value in an N=16 Python toy for this claim. Numerical substitutions can be checked by integer arithmetic.

## Existing prior art and relevant limitations
[PRIMARY] Original paper reference [BIP+18] = Dan Boneh, Yuval Ishai, Alain Passelègue, Amit Sahai, David J. Wu, *Exploring Crypto Dark Matter: New Simple PRF Candidates and Their Applications*, TCC 2018, ePrint 2018/1218, complete 63 physical pages via Research MCP; PDF SHA256 `b7ae846d2ef6e08679df3d6a9441d1fc2c84cd4364bf1a424217c64cb84b8a7e`, VERSION_UNVERIFIED. Abstract + pp.1,3: central depth-2 ACC0 **weak PRF** candidate conjecturally secure on uniform random inputs; offers distinct stronger depth-3 PRF and encoded-input PRF. Therefore using the "weak" candidate on predictable public fixed coefficients (j,i) cannot automatically invoke strong-PRF security. Using public random labels or selecting a strong PRF may be valid, but must prove domain separation, pseudorandomness of entire output family, and noise-sampling mapping. No flaw in the 2025/2057 paper is implied by its example "such as BIP+18": BIP also includes stronger variants.
[PRIOR ART] Homomorphic evaluation of AES with SIMD batched many blocks is established, e.g. *Homomorphic Evaluation of the AES Circuit* (LNCS 2012, DOI 10.1007/978-3-642-32009-5_49; abstract says 54/720 blocks in a batch). Generic "homomorphically evaluate multiple cryptographic primitive instances in parallel" is not novel.
[PRIOR ART] Vos, Conti, Erkin, *Efficient Batchable Secure Outsourced Computation: Depth-Aware Arithmetization of Common Primitives for BFV & BGV*, USENIX Security 2025 https://www.usenix.org/conference/usenixsecurity25/presentation/vos addresses batching and the importance of minimizing arithmetic depth, potentially **avoiding** bootstrapping. This does NOT verify an efficient PRF specifically meeting DKG's multi-key noise and security constraints.
[CONNECTED GITHUB EVIDENCE] `fhe-benchmarking/transciphering` README https://github.com/fhe-benchmarking/transciphering/blob/main/README.md (blob SHA 25832275debf3f0b9b484a8c16732b6c8380f9b9) describes AES CTR evaluation of many input blocks under encrypted AES key, and reference submission README uses TFHE. Shows multi-output FHE crypto circuits as a standard workload, but does not establish a direct packed BFV PRF-based threshold-DKG improvement.

## Proper limit of conclusion and potential real research
[NEGATIVE] Merely parallelizing scalar PRF instances into BFV SIMD slots at same N cannot reduce ell **full-ring** error output blocks into one; straightforward batching might lower amortized runtime per coefficient, but not abolish the ell-dependence in number of ciphertexts.
[OPEN / CRITICAL] Need not bootstrap each output ciphertext. A leveled BFV circuit can evaluate any fixed finite-depth PRF without bootstrap if chosen parameters support its depth, at possible major costs in Q, N, key size, security/time. One could also start with encrypted pseudorandom seed then use a *genuinely computational* multi-output generator, or specialized batched bootstrapping. No solution and no useful cost bound shown. Thus the original paper's tentative Ω(ell) bootstrap heuristic is neither proved nor disproved in its realistic 128-bit-secure DKG setting.
[SECURITY/INDP] Generating proper well-distributed Ring-LWE errors from a PRF with a shared seed requires domain-separated pseudorandom outputs, attention to weak vs strong PRF input security, sampler correctness, and evaluation-key joint distributions. Publicly independent error terms cannot be created statistically for free from one packed seed using only publicly known linear maps; computational PRG expansion is a different construction and needs proof.
[NOVELTY / STOP RULE] SIMD batching of cryptographic circuits is extensive prior art. A new contribution would have to exhibit a **DKG-specific** security-preserving construction whose measurable end-to-end modular/latency/bootstrapping frontier improves on the documented 4-round protocol and KLSW-based 2-round alternative, not just an O(ell) vs O(1) count from relabeling slots. This iteration establishes NO such construction.
