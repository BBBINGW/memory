## Scientific interpretation and next new architecture

**[FAIL proposed free reuse of existing source RS-coded columns]** Source's cheap NTT-friendly RS encoder operates over native base-field roots whose representative integer values differ across prime factors. The existing field-coded Merkle columns do **not** preserve direct across-prime ordinary digit equality, even on perfect common scalar Boolean inputs. Naïvely checking their canonical integer lifts violates honest completeness; no extra PCS savings obtained from **unchanged** RS columns in this way.

**[OPEN materially different]** A NEW **field-independent integer-coefficient linear encoder** `Enc_Z(x)=xG` with the SAME bounded integer generator entries over all CRT fields (e.g. 0/±1) could preserve honest cross-prime encoded column integer semantics **IF** `max_j Σ_i |G_{ij}|·(β−1)<p_min`, so no-wrap. If `G mod p_i` has large Hamming minimum distance over each native F_(p_i^d), checking already-opened source testing columns could potentially detect non-diagonal CRT digit vector differences WITHOUT more native MLE eval phase vectors; common Q and union bound must be proven. But the full architecture would require redesign of original `Enc`, simultaneously ensuring (a) sufficiently high relative distance across **all** fields including extensions, (b) near-NTT/Brakedown fast encoding not replaced by quadratic dense generic multiplication, (c) source PCS testing/evaluation binding and soundness with μ fields, (d) costly existing column openings still necessary but not extra, (e) actual 128bit overall security and privacy/Fiat–Shamir, and (f) code challenge and oracle binding order. **NONE of this was constructed or proven in I151.** This is more structural than further mask-alphabet tweaks, but simple RS root mismatch is textbook and not a paper contribution.
