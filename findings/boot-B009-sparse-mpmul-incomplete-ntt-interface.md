## Actual interface comparison (FACT)
2025/686 sec. 3 Algorithm 1 MPmul takes n RLWE ciphertexts of *exponent-encoded coefficient values* X^{u_j}, along with log B RGSW encryptions of bits v_i of an encrypted monomial shift v. It implements u(Y) -> Y^v u(Y) modulo Y^n+1 using CMUX and, for wrapped coefficients, Galois automorphism X->X^-1. Nested MPmul (Alg. 2 bin-SAB, sec.4) evaluates sparse secret multiplication via h index differences, using external products and plaintext monomial operations. It *avoids* the depth/expensive GSW multiplication of earlier DFT-style amortized methods; cost O(h n log B) external products, O(h log B) BSK control bits. Encryption ring R_Q=Z_Q[X]/(X^N+1), Q=2^64 in their concrete Table 3.
2025/696 sec.4 Alg.3 specifically assumes GSW encryptions Zi of X^{-hat{z}[i]} for ALL N incomplete-transform positions, over circulant Rtilde_Q=Z_Q[X]/(X^p-1), plus encrypted secret -sk and automorphism key switching. It computes plaintext a in transform domain, embeds base multiplication matrix A into sparse block diagonal inverse transform MA, and homomorphically applies two rounds of dot products, X=MA A then MB X. Its "free" result is exactly that A does not increase the asymptotic/dense block operation counts of the already-present two-part INTT, when incompleteness ℓ <= log2 N-α. It changes GPvL23's NTTDec, not MPmul of 2025/686.
2025/696 uses a plaintext polynomial arithmetic ring F_p[Y]/(Y^N+1) with odd prime p satisfying p≡1 mod(2N/2^ℓ) for incomplete transform. This p is conceptually distinct from the *ciphertext evaluation modulus* Q in either construction. One must not conflate them or claim their code has native NTT over Z_2^64.

## Cheapest decisive toy test — sparse monomial becomes dense in transform blocks
[INDEPENDENT DERIVATION] Take N=8, p=41, ℓ=1. p-1=40 is divisible by 8=2N/2^ℓ, but not by 16=2N, so a one-incomplete negacyclic NTT is possible while complete NTT is unavailable.
Roots of U^4+1 in F_41 are η={3,14,27,38}, all distinct and nonzero. Exact factorization in F_41[Y]:
    Y^8+1 = (Y^2-3)(Y^2-14)(Y^2-27)(Y^2-38).
CRT/incomplete transform maps polynomial f to four residues f mod (Y²-η). For a coefficient-weight-one monomial s(Y)=Y, all four residues equal Y, hence FOUR OUT OF FOUR transform blocks are nonzero. More generally any monomial Y^j is a unit modulo each Y²-η, so each of the four blocks is nonzero. A coefficient-sparse secret does NOT remain block-sparse under this transform.
[COMPUTATION] Independent Python integer modular arithmetic tested factorization and 512 randomly seeded pairs (a,b) in F_41[Y]/(Y^8+1): negacyclic coefficient product versus all four quadratic base products, each test 512/512 PASS. All j=0,...,7 coefficient-weight-one monomials had exactly 4/4 nonzero transform blocks. No cryptographic ciphertexts/native benchmarks used.
[INTERPRETATION] This falsifies the naive claim that 2025/686's h-index representation can simply be reinterpreted as a sparse list of 2025/696 NTT-domain encrypted coordinates, with unchanged key layout/cost. It does NOT prove an information-theoretic lower bound on number of new ciphertexts: encrypted transform-domain values could conceivably be derived using automorphisms, packing, key generation, or a new sparse-representation algorithm, at unknown cost. A new scheme is needed; no drop-in "free" factor.

## Additional modulus compatibility test
[DERIVATION] Over Z_(2^64), N=8 example, a primitive negacyclic 16th-root/even-order root with ψ^8=-1 cannot exist: modulo 4 any even power of an odd residue is 1 (even residue power is 0), but -1 is 3 modulo 4. Further, (Y^8+1) mod 2 equals (Y+1)^8 and is inseparable; it does not split into coprime degree-two factors over Z_(2^64) supporting the 2025/696 CRT form. Thus a direct incomplete-NTT implementation *over that same even modulus* is impossible. This does NOT bar auxiliary odd-prime RNS/CRT, nonexact FFT multiplication or special transforms, all of which require their own cost/precision analysis.
[FACT] In 2025/686 its plaintext decryption circuit uses a sparse binary/ternary polynomial over the negacyclic input ring and a 2N exponent representation; in 2025/696 plaintext p and NTT coefficients are part of a different GPvL23 partial-decryption circuit. The use of a 2^64 ciphertext modulus is NOT by itself a refutation of 2025/696, which uses different CRT moduli in its implementation.

## Cost / error / prior art gate
[FACT] 2025/696's 2.12x is against GPvL23, not 2025/686, and its DFR values differ from 2025/686's source reported targets. Any multiplicative "2.12x times 2025/686" is invalid.
[FACT] 2025/686 offers O(h n log B) external products, uses sparse RLWE secrets whose hardness/security must be separately estimated, and uses N=2048 or 8192 and q=2^64 in source Table 3. 2025/696 uses a different GSW representation (circulant X^p-1) and associated automorphism/keys, so both algebra and key layout are changed by a naive substitution.
[DECISION] FAIL direct transfer; no measurable new speedup or novel bootstrapping primitive. Do not fully kill sparse+incomplete algebraic research, but pause pending a concrete method to create transform-domain keys from h-sparse index keys without losing h-sensitive complexity, verified by cost/security/noise.
