## Algebraic interface: not intrinsically incompatible (PASS)
[FACT] 2025/686 defines RLWE cipher (a,b) with phase b-a*z ≈ (Q/t)m. 2025/1711 uses Vec-MLWE vector c=(b,a) and secret sk=(1,S), phase b+S*a ≈(Q/t)m. For k=r=1 and S=-z, ciphertexts agree up to public order/sign convention. Both can use same negacyclic ring R_Q=Z_Q[X]/(X^N+1) and one selector bit b∈{0,1}.
[DERIVATION] MPmul CMUX is c_0 + GSW(b) ⊙ (c_1-c_0). Replace GSW(b) with squared Mat-MGSW(b) key C∈R_T^{2×2} and external product C star d=round[(Q/T)(C d mod T)] mod Q on centered-lift d=c1-c0∈R_Q². By source Lemma 3.4, in an appropriate noise margin it encrypts c0 plaintext plus b(m1-m0), i.e. (1-b)m0+b m1. This is a *compatible plaintext operation*; real noise/security and parameter admissibility separate.
[DERIVATION, source's exact noiseless key form] For secret S∈R, pick independent uniform ring polynomials A0,A1∈R_T; E0=E1=0 (toy only) and set r=Round(T/Q). Then C=[[−S*A0+b*r, −S*A1+b*r*S],[A0,A1]] mod T. Its phase row sk C equals b*r*(1,S) mod T. Standard Vec ciphertext c=(m−S a,a) has phase m. Per-coordinate output rounded before phase extraction may add small rounding error.
[INDEPENDENT INTEGER REFERENCE TEST] Use N=4, Q=256=2^8, T=65537 (prime, T≡1 mod8, T>Q²=65536), plaintext t=8, scale Q/t=32, nonzero secret S=1+X, exponent monomial messages m=32X^u for u=0..7 in Z_Q[X]/(X^4+1). For each of 64 (u0,u1) pairs × two b values × 16 deterministic seeded random draws =2048 tests:
 • Sample both input Vec-MLWE public masks a0,a1 uniformly modulo Q; construct exact noise-free c_j=(m_j−S*a_j,a_j) mod Q;
 • Sample Mat-MGSW mask A0,A1 uniformly modulo T; construct C using b and r=round(T/Q)=256 with no fresh key error;
 • Center-lift componentwise c1-c0 to [-Q/2,Q/2); compute all negacyclic ring products exactly under T, center-lift, then coefficientwise nearest-integer scale Q/T, reduce to centered mod Q; add c0; decrypt phase via (1,S);
 • Target chosen monomial 32X^u; in all 2048/2048 cases max coefficient phase residual ≤1 (histogram b=0: 335 at0 and689 at1; b=1:376 at0 and648 at1), while nominal coefficient rounding margin Q/(2t)=16. Hence 0 failures in toy and both selectors 0/1 correct in all tested cases. This is a *small, insecure zero-key-noise integer emulation*, not native/secure FHE, not a proof of full 686 distribution or DFR.

## Decisive original FBS parameter/cost falsifier
[FACT] Source 2025/686 Table 3: FBS1 N=2048, q=Q=2^64, selector gadget ell_A=1, log2 beta=23; FBS2 N=8192, q=2^64, ell_A=1, log2 beta=22. These use *approximate gadget decomposition*, i.e. truncate coarse digit; not full exact 64-bit expansion. Their parameter Table 4 ell_A 12–20 covers independent HW-reducing KSK; cannot be used to artificially inflate the original selector cost.
[FACT] Source 2025/1711 Sec3.3 costs with k=r=1 and conventional ell:
 Standard ring GSW: (k+r)(ell+1)=2(ell+1) forward/inverse transforms and (k+r)^2 ell=4ell pointwise ring products.
 Squared: 2(k+r)=4 transforms and (k+r)^2=4 pointwise ring products, plus coefficientwise round(Q/T*(C d mod T)).
 For ell=1, **both have 4 transforms and 4 pointwise products** per external product at same N and same arithmetic-channel normalization. NO pure operation-count gain for this concrete baseline, unlike 1711's compared traditional ell≥2 OpenFHE/TFHE baselines.
[DERIVATION under source Cor 3.5/Section 4 sufficient parameter regime] They choose an integer Delta>=1 and require Delta Q²<T. With original Q=2^64 this entails T>2^128 (bitlength at least 129). The squared key k=r=1 is 2×2=4 polynomials with N coefficients modulo T, versus original GSW ell_A=1 key 2ell×2=4 polynomials with N coefficients modulo Q. At equal N:
 • ideal uncompressed coefficient-key bits are >=4N*129 vs 4N*64, ratio >=129/64=2.015625;
 • naive 64-bit limb arrays require at least ceil(129/64)=3 limbs per squared coefficient vs 1 for original, 3× raw coefficient storage;
 • same four ring polynomial products/transforms now act on larger moduli/multi-prime limbs; e.g. RNS/CRT would require at least three residue primes when prime limbs have <=64 bits each, if modulus T is represented that way. A nonstandard special modulus or FFT implementation may have different actual costs, so no rigorous 3× runtime lower bound is asserted.
 • actual selector key compression, prepared-NTT layout, automorphism keys, Q/T conversion, larger N required by T, and NTT-friendly modulus security remain separate unknowns. Raw scalar key bit count is not a complete BSK size.
[CONCLUSION] At fixed source Q,N and using 1711's source-proved Delta Q²<T criterion, the straightforward replacement does not reduce transforms or pointwise ring product count and INCREASES per-selector raw key coefficient bits. It is not justified as a strict end-to-end improvement. A source implementation may nevertheless optimize digit decomposition overhead or use a different faster multiply kernel; no such matched comparison exists. This is a failed *direct* optimization hypothesis, not a proof all squared-gadget amortized schemes are inferior.

## Crucial open doorway, not addressed this iteration
[FACT] 2025/1711 Sec3.1 defines the underlying Mat-MGSW scheme for T>Q, and Lemma3.4's raw error identity applies under the basic scheme; stronger Delta Q²<T belongs to Cor3.5's convenient source noise/average-case regime used for benchmarks. Thus T>Q² is NOT an algebraic necessity for CMUX correctness in every conceivable parameterization; do not conflate a sufficient noise condition with a universal impossibility.
[SPECULATION] MPmul selectors only encrypt bits 0/1 and source 686 has large Q and controlled modulus-switching stages. A carefully derived source-faithful noise/security/DFR bound might permit Q<T<<Q² with a smaller T (e.g. the 1-bit selector may tolerate a larger external-product absolute error than 1711's uniformly tight sufficient bound). This could mitigate raw modulus overhead. However even if T approaches Q from above, without a new transform/batching algorithm the 4-vs-4 base operation count persists and raw key bits cannot beat four Q-bit polys at equal N. A meaningful benefit requires faster single-level CMUX implementation, smaller N, smaller Q with equal security/DFR, or different representation/layout, all unproven.
[SECURITY] Original 686 parameter security at Q=2^64 cannot be ported to T>2^128 with same sparse RLWE secret/noise; the change in modulus and eval-key distribution changes lattice hardness, sparse-secret attacks, circular/KDM assumptions, and joint key security. Need new estimator and security arguments before any claim.
[DFR] Zero-key-noise toy cannot certify subgaussian error, automatic independence under selector reuse, final bootstrapping failure or correctness with original BSK. Any complete test needs key-switching/autormorphism errors and worst-output joint DFR.
[PRIOR ART] 1711 explicitly frames squared Mat-MGSW as ell=1 form; its use as an underlying FHEW-like primitive is prior-art-like, not yet a new composition result. A fast adaptation to MPmul might be a practical research contribution only after an independent equal-security benchmark with original 686 single-level approximate FBS keys and optimized implementation.
