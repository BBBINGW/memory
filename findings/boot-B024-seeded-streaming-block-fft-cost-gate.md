## Exact native ciphertext correctness and transform identity
One block with ℓ separate RGSW encryptions BRKi under SAME common RLWE secret t, using INDEPENDENT per-key mask rows, and weights wi(X)=X^ai−1. Each RGSW is 2d rows×2 polynomials = 4d ring polynomials (k=1 GLWE). Native block K(X)=Σ_i wi(X)*BRKi(X) is still a valid RGSW-form encrypted selector for same t, with plaintext Σ_i wi(X)*si and error Σ_i wi(X)*ei; one-hot condition ensures plaintext X^(Σ ai si)−1 as original 2023/958. Key reconstruction reproduces the originally sampled mask coefficients exactly; no change to key distribution relative to chosen SEEDED baseline, except requiring the SAME seed mask generation procedure and existing security assumptions, which must be formally carried over when deployed.
Let F be the exact negacyclic NTT, a linear R_q->R_q^N isomorphism when q≡1 mod 2N. For each ciphertext row polynomial:
  F(Σ_i wi BRKi)=Σ_i F(wi)⊙F(BRKi).
Thus FULL RGSW external product with accumulator digit polynomials h_j(ACC) is linear in K:
  ACC ⊡ K = Σ_i wi (ACC ⊡ BRKi)
under exact ring arithmetic; it can be implemented with ONE block-wide accumulator decomposition and ONE inverse transform per output polynomial. Any correctness claim about floating FFT implementation must bound floating/rounding error separately.
In coefficient domain, polynomial weighting by wi is signed rotation plus subtraction O(N) per polynomial per key (no FFT), and forming accumulated K requires no individual key transforms. Reconstruct independent masks on demand from established compressed/seeded stream and read stored bodies. All resulting K ciphertext rows share same RLWE secret, so B023 same-mask leakage does not apply; independence assumption about expanded per-key masks remains an explicit security gate.

## Source-faithful dominant operation count (per block)
Let GLWE dimension1, gadget level d, ℓ one-hot keys/block, key contains 4d component ring polynomials and each mask-seeded key holds 2d coefficient-domain body ring polynomials plus seeds, regenerating 2d mask polynomials. Accumulator decomposed digits 2d polynomial transforms; output two inverse transforms. Assume one forward/inverse FFT cost equal as simple OP COUNT proxy (real implementations differ).
  Prepared Fourier BSK (2023/958): key-side online FFT=0, accumulator forward=2d, inverse=2, total=2d+2. Key Fourier storage/transfers =ℓ*4d component spectra. Public weights twiddle/pointwise across ℓ keys. No key PRG at PBS runtime.
  Naive ON-DEMAND SEEDED per-key Fourier expansion: key forward FFT=ℓ*4d, accumulator forward=2d, inverse=2, total=4dℓ+2d+2; PRG outputs 2dℓN coefficient words. Could stream per key to avoid all-key workspace but still ℓ key transforms.
  FUSED ON-DEMAND SEEDED: coefficient sum first, key forward FFT=4d, accumulator forward=2d, inverse=2, total=6d+2; PRG same 2dℓN generated words; key summation rotations/subtractions O(4dℓN). Scratch for aggregate 4d ring polynomials, not ℓ4d. Online per-group FFT improvement vs NAIVE seeded =4d(ℓ−1). Online penalty vs PREPARED =4d.
At d=3, ℓ4: totals 8 prepared,56 naive seeded,20 fused seeded transforms; key-side saving fused vs naive=36 FFT/block, but fused vs prepared =+12 FFT/block (2.5× total-count). GSW pointwise ring multiplicative work original ~4dℓN remains, not removed by streaming. PRG and O(ℓN) weighting are new compared with prepared FFT key; no speedup follows from transform count alone.

## Explicit illustrative storage/BW cost, NOT benchmarks
Assume N=1024, 64bit torus coeff=8 bytes and N/2 complex Fourier coeff of 16 bytes each => 8 bytes per N original component, d3, ℓ4. Prepared Fourier block key ≈ℓ*4d*N*8 =393,216 B (384 KiB); seeded body storage ≈ℓ*2d*N*8=196,608 B (192 KiB) plus small seeds (excluding encryption metadata, alignments and KSK). Persistent BSK body storage ~50% compared with assumed prepared spectrum. Fused aggregate scratch 4d*N*8=98,304 B (96 KiB) before Fourier conversion; PRG reconstructs ℓ2dN=24,576 torus mask coefficients online per block. Illustrative "bytes saved/read per block" 196,608 B does not prove faster PBS; cache residency, spectra precision, input widths, and interleaving differ.
A necessary (not sufficient) condition to beat prepared on pure bandwidth roofline is:
   ΔBytes/BW_effective > T_(4d forward key FFT)+T_(PRG for2dℓN words)+ΔT_(weight aggregation)+ΔT_(memory alloc)
where ΔBytes is prepared-key traffic minus actually streamed-seeded traffic, not theoretical serialized file-size difference. If key cache is L3 resident, effective byte cost can be small; if remote HBM/PCIe-bound, streaming might help. Need representative native profiler and batch-size sweeps at equivalent security/noise to decide.
For repeated PBS under same BSK, prepared transform cost amortizes across all invocations whereas fused seeded pays 4d key FFT **every block of every invocation**, unless caching transforms; such caching trades away persistent compressed memory. Increasing PBS count makes seeded fused speedup harder, though it may remain useful for RAM-constrained single/few PBS.
