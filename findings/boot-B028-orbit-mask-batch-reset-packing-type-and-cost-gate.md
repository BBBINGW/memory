## Deterministic source-type obstruction
MPmul state consists of a list of n **RLWE ring** ciphertexts c_i encrypting monomials X^{u_i}∈R_q=Z_q[X]/(X^N+1), all need to stay individually addressable by NCMUX and CMUX in next MPmul. Published Packing KS takes n **LWE scalar** messages m_i∈Z_q and produces ONE RLWE(Σ_i m_i X^i). It does not transform a list of n arbitrary ring ciphertexts into n ordinary ring ciphertexts. There is no free inverse for the map obtained by simply replacing scalar m_i with arbitrary ring elements.

[TOY COUNTEREXAMPLE] Natural same-ring coefficient-offset pack P(m0,m1)=m0+X m1 over R=Z_q[X]/(X^4+1) with m_i monomials in X^u, u∈Z8. Distinct inputs
  (m0,m1)=(1,X) and (m0',m1')=(X²,X^7)
have SAME output 1+X² since X^8=1, but separate MPmul computation distinguishes them. Hence no deterministic unpacking algorithm can recover the pair from P alone, even error-free and even under monomial restriction. This does NOT refute source paper's scalar-input Packing KS or other tensor/multiring representations.

[EXHAUSTIVE] For N=4 and n=2, enumerate all (2N)^2=64 pairs of monomials and P(X^u0,X^u1)=X^u0+X^(u1+1) in negacyclic ring. Only33 distinct P values, 31 redundant/colliding inputs. N=8,n=2:256 pairs,129 distinct outputs,127 collisions. N=8,n=3: 4096 inputs,704 distinct outputs,3392 collisions. Exact Python tuples/integer coefficients and exponent arithmetic, no q wrap required; outputs equal modulo every ciphertext modulus. Inputs are eligible monomial *plaintexts*; this is a direct failure of a proposed packing map, not native ciphertext insecurity.

## Other naive fallbacks and quantitative obstruction
(A) Extract only ONE LWE coefficient per RLWE state: generally loses monomial exponent u_i (e.g., constant term of X and X² are both zero). Thus the original scalar packing semantics cannot retain all MPmul state information. Sample extraction in source occurs only at final output once the LUT's constant coefficient is what is needed.
(B) Extract ALL N coefficients of all n RLWE states to n*N scalar LWE samples, then apply scalar LWE-to-RLWE packing: this requires nN scalar messages and, if packed into ONE coefficient-encoded ring ciphertext per source Algorithm5, ring degree N'≥nN. With FBS1-style N=n=2048 (illustrative source-consistent) that is 4,194,304 coeff slots, an increase of ×2048 over native ring degree2048. One can spread samples among many ring ciphertexts instead; then additional keyswitching/unpacking and native MPmul ciphertext-list recreation are needed. This is a failure of naive full-coefficient extraction/packing, NOT a mathematical impossibility for special monomial ciphertext packing/tensor rings.
(C) Simply pack n ciphertexts into one arbitrary ring element without representing all original ring messages cannot achieve a free batch reset. A specialized ring/tensor representation preserving the n individually encrypted monomials may be possible but is a different full FHE scheme (key format, secret, GSW operation, dataflow and security must be reconstructed); not implied by source Algorithm5.
