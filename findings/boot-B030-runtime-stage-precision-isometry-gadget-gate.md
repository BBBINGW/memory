## Decisive gate 1: exactly one gadget digit, and both its ciphertext rows are essential
A standard GLWE-dimension1, one-level approximate RGSW key has l=1 and (k+1)=2 gadget rows, each with 2 ciphertext polynomials. There is no positive smaller l. Skipping its only decomposition level returns zero selector product; skipping only one of the 2 rows is wrong on generic ciphertexts.
[REFERENCE EXACT TEST] Minimal noiseless scalar projection of RGSW embedding: q=256, gadget base B=16, G=q/B=16, secret s=1. For all b,a∈{0,16,...,240}, take ciphertext phase m=b−a*s modq. Noiseless selector bit1 key rows equal G*I_2, decomposed digits (b/G,a/G), so full gadget product gives exactly m. 256/256 full pass. Skipping the body row gives wrong outputs 240/256 (whenever b≠0); skipping mask row also wrong 240/256 (whenever a≠0). This is a diagnostic algebraic necessary test, not an actual RGSW encryption implementation.
Changing base/δ for each call while retaining fixed l1/key would change rounding residual rather than remove an expensive level; no fewer key rows, forward/inverse transforms or pointwise RGSW products. To reduce numeric word width one needs a DIFFERENT NTT/FFT/external product implementation (e.g., f32 vs f64, restricted modulus/CRT) plus separate numerical noise/DFR and prior art checks; not supplied by mere gadget-level switching.

## Decisive gate 2: signed negacyclic permutation is an exact isometry
Let n be number of RLWE(X^u_j) state ciphertexts, R=Z[X]/(X^N+1), sigma:f(X)->f(X^-1). For stage i with shift d=2^i and selector bit v_i:
  if v_i=0, entire vector state unchanged.
  if v_i=1, new state at index j is sigma(state[(j−d) modn]) if j<d, otherwise state[j−d].
For the message and for *preexisting* decryption-phase error polynomials, this is a bijective signed permutation of coefficients: sigma maps (e0,e1,...,e_(N−1)) to (e0,−e_(N−1),...,−e1). Consequently stage propagation operator P_i(v_i) satisfies P_i(v_i)^T P_i(v_i)=I over the integer coefficient representation and ||P_i(v_i) E||²=||E||². Composing ANY number of MPmul stages preserves norm. This is the faithful native plaintext/Error-transport operation for correctly evaluated encrypted selectors, NOT an analysis of newly generated GSW/KS errors or rounding.
[FALSIFIER] A planned heuristic "early noise is harmless because later MPmul stages dilute it" (or "late stages inherently less important") is FALSE: for each stage a unit basis error can survive in exact norm to final output. In the independent isotropic injected-noise heuristic Cov(e_t)=σ_t²I, output total expected energy is sum_t nN σ_t², regardless of its injection *position*, subject to independent errors. Real source errors may be correlated and NCMUX noise may have distinct cost, so don't claim equal overall actual DFR for all stages.

## Actual call-count/precision-sensitivity table from author source
Use source noise_estimator's B1/FBS1 combination n=2048, h=39, r_prec=7 (rotation bound B=128). Number of MPmul calls M=h+1=40. Each MPmul executes exactly n*r_prec=14336 total CMUX/NCMUX operations; NCMUX with automorphism Σ_(i=0)^6 2^i=127, normal CMUX=14209. Across full chain 40 calls: total CMUX573440, NCMUX5080, ordinary CMUX568360.
Within *one* MPmul, for each bit-index i the same specific RGSW encrypted selector is used at all n positions at that stage: NCMUX count2^i, normal CMUX n−2^i. NCMUX fraction grows from1/2048 to64/2048 across i=0..6 (≈0.05%–3.125%) but there are always n RGSW products per bit-key. Source has DIFFERENT selector sets for each of the 40 MPmul calls (secret gap encodings), so "the exact same key across all MPmul stages/calls" is not literally true. The X->X^-1 automorphism key is the reused public key across NCMUX calls.
Crucial subtlety: Stage-dependent NCMUX extra KS noise and output dependencies CAN make optimal OFFLINE parameter allocation nonuniform; the signed-permutation isometry only rejects a proposed inherent early/late attenuation benefit. However OFFLINE heterogeneous per-key selection is already the 2025/1892 line and OpenFHE Sep2026 integration. Selecting smaller precision for normal CMUX but larger precision for rare NCMUX using only the same 1level key requires a new secure/faster arithmetic backend or added key variants; cannot be assumed free. The total 573440 calls do not automatically yield 573440 independent noise samples due key reuse; any real DFR needs a source-faithful correlated-noise analysis.
