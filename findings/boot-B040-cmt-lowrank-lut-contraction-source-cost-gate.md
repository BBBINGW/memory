## Core exact construction and correctness theorem [DERIVATION]
Source CMT Eq(5)/Alg6 computes f(x)=L(x)^T Y R(x) where Y is reshaped LUT, L∈(CKKS ciphertext)^A and R∈(CKKS ciphertext)^B are Kronecker products of encrypted Kronecker-delta digit selectors, A*B=P (or nearest padded rectangle); plaintext Y_ij=f(index(i,j)).
For exact real/integer PUBLIC rank factorization Y=U V^T, U∈R^(A×r), V∈R^(B×r),
    L^T Y R = Σ_(t=1)^r (Σ_i U_it L_i)*(Σ_j V_jt R_j)
in the CKKS plaintext arithmetic ring and for ANY L_i,R_j, not just onehot selectors. Thus exact identity remains true even if L,R encode upstream digit noise (algebraic error) and there is NO NEW upstream selector leakage in ideal arithmetic. This conclusion does NOT include fresh rescale/relinearization errors introduced by changing the evaluation schedule.
Original final Alg6: P plaintext×ciphertext scalar products in row-by-column LUT contraction, A ciphertext×ciphertext products for per-row selection, plus additions and two upstream KProduct calls. Factor schedule: r(A+B) public plaintext×ciphertext multiplies, r ciphertext×ciphertext multiplies, plus additions and SAME upstream KProduct calls. Balanced A=B=√P: scalar reduction only if 2r√P<P => r<√P/2; ct×ct reduction if r<√P. At r=√P generic full rank, scalar products DOUBLE (2P), ct×ct remain√P, so universal random LUT optimization FAIL. Scalar multiply by ±1 or 0 might be implemented cheaper than general plaintext multiplication; these exact counts are a pessimistic GENERIC per-coefficient model, not real FFT/CKKS timings.
Depth: each L/R selector has same Kronecker-product multiplicative depth; both outer weighted sums use plaintext operations; final r products can be at same depth as original A products, as long as CKKS scale/level operands are aligned. In original §7 lazy relinearization original relinearizes some intermediate selector sides and postpones final rescale; factor method may change which intermediate ciphertexts to relinearize and adds different plaintext scales, so NO unconditional exact level/latency equality without CKKS source implementation.
Noise: preexisting upstream digit-selector errors have exact same ideal bilinear polynomial in original and factor schemes; new CKKS errors and approximate SVD/truncation potentially differ. If an approximate rank-r factorization Y≈Y_r, onehot-input correctness requires each LUT entry approximation error |Y_ij−(Y_r)_ij| less than remaining message margin, in addition to all native CKKS noise. No structural ability to approximate arbitrary discontinuous random LUT accurately at small r.
