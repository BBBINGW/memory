## Construction and exact mathematical test
Let h blocks each of length B=N/h, with onehot secret indicator s_(k,i) and independent public phase u_(k,i)=exp(2pi*i*c_(k,i)/q). Original selected phase U_k=Σ_i s_(k,i)*u_(k,i); ciphertext result Z=product_(k=0)^(h−1) U_k, encrypted with balanced multiplication tree depth log2h.
Proposed joint selector for pair (2k,2k+1): P_(k,i,j)=s_(2k,i)*s_(2k+1,j), onehot over B² indices, with public joint phase W_(k,i,j)=u_(2k,i)*u_(2k+1,j) (can compute plaintext-side since c public). Then V_k=Σ_i,j P_(k,i,j)*W_(k,i,j)=U_(2k)*U_(2k+1) EXACTLY; multiply h/2 resulting encrypted V_k, depth log2(h/2) i.e. saves precisely one online multiplication/rescale level, conditional on supplying all encrypted pair selectors at keygen.

## Fatal memory representation cost for naive direct onehot table
Each pair has B² separate onehot indicators; h/2 pairs → (h/2)B² = NB/2 encrypted key plaintext coordinates. Packed CKKS ciphertext has N/2 slots. Thus for DIRECT ciphertext-slot packing of independent pair coordinates, need at least ceil(((h/2)B²)/(N/2))=B packed CKKS ciphertexts, vs exactly TWO original BSK ciphertexts. At paper single-slot N32768,h64,B512: joint pair indicator count 32*512²=8,388,608, with N/2=16384 slots each → at least 512 ciphertexts, versus original2: 256x more BSK ciphertext OBJECTS, not full key RSS or guaranteed ciphertext bytes. No count of additional rotations/trace, which also grow. Product depth6→5 theoretically, but key-memory cost overwhelms initial source's main performance goal under the straightforward scheme. ## Why quadratic pair keys cannot come free from original encrypted BSK
Original BSK publishes encryptions of degree-1 secret functions s_(k,i). Pair key contains degree-2 monomials s_(p,i)*s_(q,j). Any computation using ciphertext additions, public scalar multiplications, Galois rotations and other PUBLIC LINEAR operations of the original encrypted BSK yields an AFFINE function of the two independent onehot block positions. For B>=2 a mixed rectangle cross-difference across secret choices (i0,j0),(i0,j1),(i1,j0),(i1,j1) is 0 for EVERY separable affine f(i,j)=a(i)+b(j)+c, but equals 1 for pair indicator 1_(i=i0,j=j0). Therefore pair indicators are not derivable for all valid secret choices without a secret-dependent ciphertext multiplication (costing the level we aim to save), or new independent encryptions of degree2 secret products at keygen. This changes evaluation-key transcript, potentially degree-2 KDM/circular-security assumptions, and additional noise/key distributions; no security reduction here.
The PUBLIC phase features W_ij(u,v)=u_i*v_j for independently chosen public phase coordinates are B² linearly independent characters: under uniform public roots their Gram matrix is identity. Python exact-domain enumeration and complex tolerance:
