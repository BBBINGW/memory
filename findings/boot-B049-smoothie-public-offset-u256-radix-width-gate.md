DECISIVE REPRESENTABILITY COUNTEREXAMPLE [DERIVATION]: In w=2*n bit plaintext modulus 2^w, U256 cannot represent the positive integer 2^w for w>=256, as source computes directly. At n=128,w=256, the modulus expression U256::ONE<<256 cannot produce mathematical modulus 2^256; exact runtime panic/wrap behavior depends on type implementation and was NOT executed. At n=256,w=512, even some valid PUBLIC correction values have nonzero coefficients above bit255 and are not representable by U256. Take C=3*2^300 and off=0. C mod2^256=0, but correct correction -C mod2^512 is nonzero. C=0 and C=3*2^300 collide in U256 but not in 512bit target ring. No algorithm seeing only fixed U256 correction can produce correct output for both. This is a necessary information-domain obstacle, not a proven native decryption failure or published security weakness.

MINIMAL PUBLIC REPAIR [DERIVATION]: Over Z/(2^w), the intended expression (off+2^w-(C mod2^w)) mod2^w equals (off-C) mod2^w. Avoid materializing 2^w. Encode off and C as little-endian public base-4 limbs of length n (w=2n). For i=0..n-1, compute d=off_i-C_i-borrow, if d<0 then out_i=d+4,borrow=1 else out_i=d,borrow=0. Discard borrow above n; output limbs represent (off-C) mod4^n. Then construct one trivial radix ciphertext with those PUBLIC limbs. No fresh PBS/CMUX, no new key distribution required by pure public arithmetic; metadata/degree/carry representation and actual native tfhe-rs constructor remain unverified. This is elementary implementation arithmetic, NOT new crypto.
