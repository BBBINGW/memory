## Reproduced operation-count gate
One pure Python deterministic script, b080_novelty_cost_gate.py, models exact paper Algorithm3 pair tree and Algorithm6 for radix16 and LUT bits L13..20. It enumerates LSD split choices and optimizes independent KProduct tree order via subset DP, requiring no higher multiplicative depth. Source split fixed j_src=ceil(L/8). Two separate interfaces:
A fully padded, all digit delta ciphertext vectors length16 (most conservative unchanged ciphertext support): L17/18/19/20 source8704 ct-ct vs candidate4864 (-44.12%) depth3 both; L13..16 unchanged 768 depth2.
B mathematical effective-digit model, last digit 2^r values for r=L mod4 (not established correct for physical CKKS, may discard noisy invalid selectors): at L17:8480->1056 (-87.55%), L18:8512->1600 (-81.20%), L19:8576->2688 (-68.66%), L20:8704->4864 (-44.12%). Never claim B variant as a native speedup.
For L18 even the conservative save3840 ct-ct products is small relative to P=262144 required public LUT MulInt and O(P) additions. Surrogate with ct-ct cost c times public MulInt and all other operations assumed free: speed=(262144+8704c)/(262144+4864c), c1:1.0144x, c4:1.0545x, c8:1.1020x, c16:1.1807x, c32:1.2941x. Illustrative only, no native time estimate or upper bound when other costs/levels differ.
[IMPORTANT] Section7 fully relinearizes MSD vector before the P scalar LUT multiplications while treating last LSD product lazily. In L18 model moving split3+2 to2+3 makes MSD leaf vector count 64->1024 (effective) or256->4096 (full padded), potential 16x increase in fully relinearized outputs, although MSD depth increases 1->2 with lower RNS limbs. This cost can overwhelm saved products; exact level/noise/precision schedule requires native study.
