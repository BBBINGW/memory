## Primary technical hypothesis
Coron–Köstler SPRU author code implements a nondefault stride parameter t that reduces encrypted selector key ciphertexts and their online ct-pt products by factor t. Can this be treated as a mere storage/online cost improvement while inheriting the paper's ambient-N 128-bit security estimate? Minimal falsification: exhibit actual public key-switching transcripts that project to RLWE instances over ring degree N/t, and validate exact equations and a tiny public-only key recovery. The author code already has the optimization: this audit does NOT claim to invent the stride method.

## Exact public subring-RLWE reduction
Let t>1 divide N and B=N/h, and t divide B. R_p=F_p[X]/(X^N+1), R'_p=F_p[Y]/(Y^(N/t)+1), Y=X^t. The source stride gives secret s(X)=s'(X^t) in R'_p. For any public P' limb sample (a,b), write a(X)=sum_(r=0..t-1) X^r a_r(X^t), similarly b,e. Since b=-a*s(X)+e mod p and multiplication by s'(Y) does not mix the exponent residue classes mod t, coefficient comparison gives FOR EACH r:
 b_r(Y)=-a_r(Y)*s'(Y)+e_r(Y) mod (Y^(N/t)+1,p).
All t projected equations are zero-RLWE samples under SAME short secret s' of dimension N/t, with original projected small error e_r. Independent uniform polynomial a provides uniform independent a_r. Original argument works modulo EACH publicly exposed P' RNS prime, not the Q_l limbs that contain P'*sOld. This is an exact public distribution reduction and requires no guessing dense secret or original plaintext.
It does NOT by itself quantify 128bit security, actual block-hybrid/MITM/BKZ or LWE estimator cost, or full KDM security. Explicit cryptanalytic estimation is indispensable before alleging a break. Simply noting entropy drop without confirming zero-encryption P' exposure would have been insufficient.

## Parameter sensitivity and firm caution
At N=32768,h64,B512,n8 original 16 selector ciphertexts:
t1 -> key ct16, dimension32768, support entropy (h-1)log2(B/t)=567 bits, quarter exponent 141.75;
t2 -> key ct8, dimension16384, entropy504, quarter126.0;
t4 -> key ct4, dimension8192, entropy441, quarter110.25;
t8 -> key ct2, dimension4096, entropy378, quarter94.5;
t16 -> key ct1, dimension2048, entropy315, quarter78.75.
The quarter-support exponent comes from a lower-bound S^(1/4) discussion of a particular May-style attack in the paper. It is NOT a certified upper bound on attack complexity and values below128 do NOT themselves prove insecurity. The projected RLWE samples in smaller ring are the decisive additional security fact. The 2n/t reductions concern only selector key/material/ctpt counts, not full latency, keyswitch bytes or precision. The default source benchmark sets t=1 and is unaffected by the subring projection.
