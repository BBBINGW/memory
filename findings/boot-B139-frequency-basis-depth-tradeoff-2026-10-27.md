# BOOT-B139 — Frequency-basis depth/root tradeoff in ePrint 2026/2119

- Date: 2026-10-27 (Asia/Singapore)

- Status: COMPLETE_AS_SOURCE_GATED
- Decision: SIGNED_DIFFERENCE_LOW_NOVELTY / MULTILEVEL_MATH_PASS_BUT_PARAMETER_AND_PRIOR_ART_GATED
- CODEX_REQUIRED: NO

## Question

2026/2119 can evaluate a degree-d real trigonometric FBS polynomial by directly blind-rotating d positive frequencies. If one additional multiplication level is available, it explicitly follows SWIFT (ePrint 2026/1163) and uses an order-two additive/GPSP basis A so every frequency is either a seed or a+b.

Can conjugation-assisted differences or more reconstruction depth reduce the number of expensive blind-rotation roots enough to form a new useful direction?

## Source boundary

2026/2119 full source is available and audited.

SWIFT ePrint 2026/1163 full text is currently unavailable to the research MCP:
- official ePrint PDF: HTTP 403;
- no exact-title arXiv copy found;
- fixed GitHub ePrint mirror has no PDF.

Public metadata verifies the title/authors, but not SWIFT's exact construction. Hence this round does not make a novelty claim about anything potentially covered by SWIFT.

## 1. One-extra-level baseline from 2026/2119

Section 7 states:
- direct path: d positive-frequency blind rotations;
- negative frequencies are free up to ciphertext conjugation for real inputs;
- optional one-extra-multiplication-level path: choose A, blind-rotate only z^a for a in A, and reconstruct every missing positive frequency as z^(a+b)=z^a z^b;
- choosing A is an order-two Global Postage-Stamp Problem.

Thus positive-sum additive-basis reconstruction is already explicit prior art in the target paper/SWIFT lineage.

## 2. Signed-difference extension

Because conjugation gives z^(-b)=conjugate(z^b) for real m,

z^(a-b) = z^a * conjugate(z^b)

uses the same one ciphertext-ciphertext multiplication depth as z^(a+b).

Therefore a one-level basis can cover

A union (A+A) union |A-A|.

This is algebraically valid.

### Exact small-degree enumeration

A local exact search over integer seed sets A subset {1,...,d} gives:

- d=12:
  - positive-sum basis minimum = 4, e.g. {1,3,5,6};
  - signed sum/difference basis minimum = 4;
  - no root-count gain.

- d=40:
  - positive-sum basis minimum = 9;
  - signed sum/difference basis minimum = 7, e.g.
    A={2,11,13,14,18,19,21}.
  - exhaustive enumeration excludes any signed basis of size 6.

So the signed trick can reduce root count in some degrees, but not uniformly.

### Novelty gate

This is weak as a research contribution:
- classical additive combinatorics has long studied difference bases / sparse rulers for covering intervals by differences;
- conjugation as a free negative-frequency source is standard CKKS algebra;
- a public non-author 2026/2119-style implementation in virtualsecureplatform/TFHEpp already implements an optional frequency-basis mode with differences and conjugates the second retained root when reconstructing a-b.

That public code is not publication prior art by itself, but it strongly indicates that the construction is an obvious/independently discovered implementation variant.

Decision:
PASS_ALGEBRA / FAIL_NOVELTY_STRENGTH for signed-difference basis.

## 3. Multi-level additive bases

With L ciphertext-multiplication levels dedicated to frequency reconstruction, a balanced product can synthesize a frequency whose exponent is a sum of up to

h=2^L

seed exponents.

The natural combinatorial object is therefore an order-h additive/postage-stamp basis, not just the order-two GPSP used by 2026/2119.

Exact small examples for d=40:
- L=1 (h=2): minimum positive-sum seed count = 9.
- L=2 (h=4): minimum = 4; example {1,3,7,16}.
- L=3 (h=8): minimum = 3; example {1,2,6}.

For h=4, r=3 cannot cover 40 values even at the counting level because the number of nonempty multisets of at most four elements from three seed types is at most C(7,4)-1=34, so r=4 is optimal.

This is a genuine root/depth tradeoff.

## 4. Arithmetic cost tradeoff

If all d positive frequencies are ultimately needed and r are generated by blind rotation, at least d-r additional frequency ciphertexts must be created. Each new frequency requires at least one ciphertext-ciphertext multiplication in an ordinary arithmetic circuit.

An idealized cost is therefore

T(r) ~= r*C_BR + (d-r)*C_mul,

plus conjugations/additions/scheduling.

Reducing r is valuable only when a blind rotation is substantially more expensive than a ciphertext multiplication and when the extra multiplicative depth does not force a larger parameter set.

For d=40:
- one-level r=9 -> at least 31 reconstructed products;
- two-level r=4 -> at least 36 products;
- three-level r=3 -> at least 37 products.

So moving 9->4 roots saves five blind rotations at the price of at least five additional ciphertext multiplications plus one extra depth level.

## 5. Critical modulus/security budget obstruction

2026/2119 Table 2 uses:
- LL13: N=8192, log(PQ)=218;
- LL14: N=16384, log(PQ)=437;
- HT14: N=16384, log(PQ)=438;
- HT15: N=32768, log(PQ)=881.

Microsoft SEAL's standard tc128 coefficient-modulus maxima are:
- N=8192: 218 bits;
- N=16384: 438 bits;
- N=32768: 881 bits.

Thus the paper's parameter families are at or essentially at the standard 128-bit modulus ceiling for their ring degree.

Therefore extra reconstruction depth is not free at fixed N:
- LL13 has no spare standard modulus bits beyond its stated 218-bit budget;
- adding another roughly 20-bit multiplication prime directly would exceed the standard N=8192/tc128 bound;
- similarly HT14 and HT15 are exactly at the standard cap, and LL14 is only 1 bit below.

Any extra level must instead:
1. consume/reallocate an existing level/precision budget, or
2. increase ring degree, which materially changes latency and destroys a direct comparison to the 8.2 ms LL13 result.

The paper says the LL configurations retain one multiplication level after bootstrapping. The optional one-level GPSP path in Section 7 therefore already competes with an extremely tight level/modulus budget; the manuscript does not provide enough source detail to infer that arbitrary further reconstruction levels can be added while preserving the reported output-level budget.

This is the main value obstruction for L>=2.

## 6. B139 decision

- Positive-sum one-level basis: already explicit in 2026/2119/SWIFT lineage.
- Signed differences: algebraically valid and can reduce roots (d=40: 9->7), but novelty is weak and independently implemented publicly.
- Multi-level order-2^L bases: mathematically strong root reduction (d=40: 9->4->3), but extra depth collides with a parameter family already at the standard 128-bit modulus ceiling.
- Exact SWIFT prior-art boundary: SOURCE_GATED until ePrint 2026/1163 full text is supplied.
- No Codex/native benchmark justified.

Overall:
PARK signed-difference.
MULTILEVEL = CONDITIONAL / SOURCE_GATED / PARAMETER-GATED, not an active implementation candidate.
