## Question

For a standard dense/unstructured binary first-layer secret, can multiple coordinate-dependent selector keys be consolidated into one block key and processed with one external product, without:
- changing the secret distribution;
- enumerating exponentially many block states;
- adding nonlinear ciphertext operations;
- or reconstructing the original large key family?

## Dense-block affine-consolidation no-go lemma

Let a secret block be
    s = (s_1,...,s_b) in {0,1}^b.

For public blind-rotation monomials u_i = X^{a_i}, define d_i = u_i - 1.

The exact block multiplier is

    F(s) = product_i (1 + s_i d_i).

Suppose a proposed "free packing" scheme takes only encrypted affine information about the individual secret bits and, by public linear combination, forms one selector for one external product. At the plaintext level this means it can produce only a function

    G(s) = c_0 + sum_i c_i s_i

for public ring coefficients c_i.

For i != j, define the second Boolean finite difference at the all-zero secret:
    Delta_i Delta_j H(0)
      = H(e_i+e_j) - H(e_i) - H(e_j) + H(0).

Every affine G satisfies
    Delta_i Delta_j G(0) = 0.

But for the exact blind-rotation block factor,
    Delta_i Delta_j F(0) = d_i d_j
                         = (X^{a_i}-1)(X^{a_j}-1).

For ordinary TFHE/FHEW parameters there exist public a_i,a_j for which this ring element is nonzero. Since blind rotation must handle arbitrary valid ciphertext masks, an affine one-selector consolidation cannot be correct in general.

Therefore:

    DENSE_BLOCK_FREE_AFFINE_CONSOLIDATION = FAIL.

Equivalent interpretation: the exact dense-block multiplier contains higher-order secret terms
    s_i s_j, s_i s_j s_k, ...
that cannot be generated by a public linear combination of per-coordinate encrypted secret values.

This is a model-specific no-go: it rules out "pack existing coordinate EVKs and linearly combine them into one selector." It is not a universal lower bound against all conceivable cryptographic constructions.

## Why block-binary/sparse methods escape the lemma

If each block has Hamming weight at most one, then all products s_i s_j with i != j vanish on the support of the secret distribution. Hence

    product_i (1+s_i d_i)
      = 1 + sum_i s_i d_i

on that restricted support.

This is exactly the algebra exploited by:

### Lee–Min–Seo–Song, ASIA CCS 2023 / ePrint 2023/958

"Faster TFHE Bootstrapping with Block Binary Keys"

They sample the LWE secret from a block-binary distribution: n=ell*k bits split into k blocks, each with Hamming weight at most one.

Their new blind rotation performs:
- k external products rather than n;
- n public scalar multiplications/additions on TRGSW ciphertexts.

The paper explicitly explains that each block factor becomes affine because at most one selector bit is nonzero.

Their implementation reports:
- gate bootstrap: about 10.5 ms -> 6.4 ms;
- bootstrapping key: 109 MB -> 60 MB.

## Dense-secret escape route: Bootstrapping Key Unrolling (BKU)

For an unrestricted dense binary block of size u, prior art does not pretend the cross terms disappear. Instead it enumerates block secret states.

LFHE ePrint 2023/767 summarizes the BMMP/ZYLZD unrolling variants:

- group u secret coordinates;
- for each possible block value v, encrypt an indicator delta_{v,l};
- apply one block accumulation;
- reduce sequential blind-rotation iterations from n to n/u.

This pays an exponential block-state price:
    conventional unrolling key family = O(n * 2^u)
(up to variant-specific /u constants).

This is exactly the expected consequence of the high-order secret terms.

## LFHE already compresses the unrolled client-side key

Kim–Lee–Deryabin–Eom–Choi,
"LFHE: Fully Homomorphic Encryption with Bootstrapping Key Size Less than a Megabyte",
ePrint 2023/767.

The paper packs many values B^j s_i into coefficients of a small number of RLWE plaintext polynomials, transmits encryptions of the packed polynomials, then reconstructs the original RGSW blind-rotation keys server-side using:
- O(log N) automorphism keys;
- coefficient extraction;
- a square key encrypting z^2.

For ordinary binary BRK it states asymptotically O(log N) transmitted key objects (under n/N<1).

With key unrolling, its Table 1 gives:
- conventional CGGI/BMMP/ZYLZD: O(n * 2^u) key objects, NTT count O(1/u);
- proposed packed form: O(log N + 2^u) transmitted key objects, NTT count O(1/u).

The paper explicitly warns this is not a free comparison:
- key reconstruction adds noise;
- higher parameters are required;
- server-side reconstruction regenerates the RGSW objects.

Its implementation reaches under 1 MB transmitted key in one parameter set, with roughly 2x bootstrapping-time overhead relative to the original method.

## Direct NTRU block-key closure: Feng–Wu–Lin–Xiang, ePrint 2025/2311

After the first version of this finding was written, a direct NTRU-specific source was recovered:

"Accelerating NTRU-based Bootstrapping with Block Key Distributions",
ePrint 2025/2311.

It applies exactly the secret-support route to NTRU blind rotation:
- block-binary and block-ternary LWE secret distributions;
- n/ell external products instead of n;
- combination with key unrolling yielding n/(2 ell) external products in the stated construction.

For ell=4, the paper reports a 1.12x speedup over the CHES 2024 key-unrolling baseline and 1.73x over FINAL in its 128-bit-security experiments. It states that the latter two tested variants increase memory by less than 15 MB relative to the CHES 2024 unrolling method.

More importantly for the structural gate, the paper explicitly exposes the same tradeoff when block keys are combined with dense-state unrolling: the RHS contains ell^2+2ell nontrivial terms per step, so the method generates n(ell+2) evaluation keys in that construction.

## Tradeoff closure

For dense/unstructured secrets, the obvious family-count reduction mechanisms are now all covered:

1. Public linear packing of ordinary per-bit EVKs:
   FAIL algebraically because dense block factors contain nonzero higher-order secret terms.

2. Constrain the secret support so cross terms disappear:
   PRIOR ART (block-binary / partial / sparse secrets).

3. Enumerate block secret states and process one block at a time:
   PRIOR ART (BKU).

4. Compress the exponentially enlarged unrolled key for client transmission:
   PRIOR ART (LFHE packing/reconstruction).

5. Apply unrolling directly to NTRU blind rotation:
   PRIOR ART (TCHES 2024).

6. Compress bytes by seeded/PRG techniques:
   separate mature prior art; it does not remove the underlying dense-secret algebraic dependence.

## What is not ruled out

This finding does not prove a universal lower bound on every possible blind-rotation representation.

A genuinely new result would need a mechanism outside the known tradeoff triangle, e.g.:
- a new cryptographic representation supporting dense-block inner-product exponentiation without state enumeration;
- a provable asymptotic improvement in server-resident/online key traffic, not merely client transmission;
- or elimination of a different expensive stage/key family.

Absent such a mechanism, do not spend further BOOT cycles on generic coordinate-EVK packing.
