## 1. addTheseMatrices globally rebuilds the routing map

Pinned source:

\[
\texttt{addTheseMatrices(sKey, automVals, keyID)}
\]

does:

1. for every requested automorphism value \(k\),
   \[
   \texttt{GenKeySWmatrix(1,k,keyID,keyID)};
   \]
2. after all additions,
   \[
   \boxed{\texttt{sKey.setKeySwitchMap();}}
   \]

Thus the extra RM10 matrices are not merely lookup entries used only by explicit RM10 calls.

They become edges in the same global same-key automorphism graph used by every later \`smartAutomorph\`.

## 2. setKeySwitchMap is a BFS over all same-key direct matrices

For key ID \(i\), HElib first gathers every matrix satisfying:
- target key ID \(i\);
- source secret power \(1\);
- source key ID \(i\).

Each matrix contributes an automorphism edge labelled by its \`powerOfX\`.

The routine then runs FIFO breadth-first search from node \(1\) in the automorphism group and records the first matrix edge used to reach every reachable node.

Therefore the map encodes shortest-hop routes in the Cayley graph generated by the available direct matrices.

Adding new direct matrices changes the graph and can reduce the BFS distance of automorphisms that are already present in comparator algorithms.

## 3. smartAutomorph follows the recomputed map, not a fixed algorithm-local route

For requested automorphism \(k\), \`Ctxt::smartAutomorph(k)\` repeatedly executes:

\[
W\leftarrow\texttt{getNextKSWmatrix}(k,keyID),
\]

\[
a\leftarrow W.\texttt{fromKey.powerOfX},
\]

\[
\texttt{automorph}(a),
\]

\[
\texttt{reLinearize}(keyID),
\]

\[
k\leftarrow k a^{-1}\pmod m
\]

until \(k=1\).

Thus unchanged high-level Aung/HElib comparator code can execute a different number and sequence of physical KS operations solely because the evaluation-key set changed.

This falsifies the primary hypothesis.

## 4. Plaintext semantics are unchanged

Changing a multi-hop route does not change the requested automorphism.

If the selected edge sequence is

\[
a_1,\ldots,a_h,
\]

the \`smartAutomorph\` loop terminates only after

\[
k(a_1\cdots a_h)^{-1}=1,
\]

so

\[
a_1\cdots a_h\equiv k\pmod m.
\]

Each key switch relinearizes the automorphed secret representation back to the same base key.

Hence the comparator still evaluates the same high-level:
- trace;
- linear transformation;
- Corr./TnM algorithm;
- thin bootstrap algorithm.

The difference is in:
- physical hop sequence;
- fixed evaluation-key error coordinates read;
- HElib noise ledger;
- latency.

Therefore the correct classification is:

\[
\boxed{
\text{same source-level algorithm, augmented evaluation-key execution graph}.
}
\]

It is not byte/operation-identical stock-keyset execution.

## 5. Adding edges cannot increase shortest physical-hop distance

Because \`setKeySwitchMap\` uses BFS, enlarging the edge set cannot increase the graph-theoretic shortest-path distance from node \(1\) to any already reachable automorphism.

Therefore, for a fixed requested automorphism:

\[
\boxed{
h_{\rm BSGS+10}(k)\le h_{\rm BSGS}(k).
}
\]

This is a physical-hop-count monotonicity statement.

It does **not** prove monotonicity of:
- wall-clock latency;
- final capacity;
- actual sampled error;

because a different path uses different matrices and digit decompositions.

Still, the augmented comparator is never deliberately made weaker in physical KS count by adding the ten edges.
