## 1. Standard HElib bootstrapping key setup is a mixed resource model

Pinned tests/GTestThinboot.cpp uses:

  context.enableBootStrapping(...);
  secretKey.GenSecKey();
  addSome1DMatrices(secretKey);
  addFrbMatrices(secretKey);
  secretKey.genRecryptData();

This is NOT "FULL for every dimension".

Pinned include/helib/keySwitching.h declares:

  addSome1DMatrices(...,
                    bound=HELIB_KEYSWITCH_THRESH=50)

while

  addFrbMatrices(...)

is the maximal FULL Frobenius routine.

For a 1D generator dimension:
- order <= 50 -> add1Dmats4dim -> HELIB_KSS_FULL;
- order > 50 -> the active pinned implementation uses baby-step/giant-step matrices and
  HELIB_KSS_BSGS.

Thus the correct standard comparator description is:

  stock/default 1D strategy
  +
  FULL Frobenius strategy,

not "all dimensions FULL".

## 2. Current m=32768 forces mvec=[32768]

HElib requires mvec to be a pairwise-coprime prime-power factorization whose product is m.

Current:

  m = 32768 = 2^15

is itself one prime power and has no nontrivial decomposition into pairwise-coprime prime powers.

Therefore, up to trivial omission of units:

  rcData.mvec = [32768].

The current EvalMap has exactly one factor:

  nfactors = 1.

## 3. The pure EvalMap has one outer size-2 dimension and one inner Frobenius dimension

For m=32768:

  phi(m) = 16384.

Current p=5 has:

  d = ord_32768(5) = 8192.

Hence the number of physical slots is:

  nslots = phi(m)/d = 2.

In the pinned EvalMap constructor with nfactors=1:
- dvec[0]=8192;
- the reduced signature size is
    16384/8192 = 2;
- Step1Matrix is therefore a 2-way outer block transformation;
- each block has extension degree d=8192.

Pinned BlockMatMul1DExec executes this structure using:
- the ordinary outer generator dimension dim=0;
- Frobenius dimension dim=-1 inside each extension block.

So the entire current pure inverse requires only:

  OUTER: order-2 1D automorphism resource
  INNER: order-8192 Frobenius resource.

There are no additional factor dimensions.

## 4. Stock addSome1DMatrices already gives FULL support for the outer order-2 dimension

The default 1D threshold is 50.

The stock default setup already contains the maximal resource for this dimension.

## 7. normal_basis=false does not change the required automorphism dimensions

Pinned EvalMap.cpp constructs the same:

- MatMul1DExec / BlockMatMul1DExec structure

Thus no additional automorphism/key-switch handle can arise solely from disabling the normal
basis multiplication.
