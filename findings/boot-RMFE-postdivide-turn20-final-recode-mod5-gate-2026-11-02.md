## 1. Mod-5 reduction of the RMFE maps

Let:
  R4 = Z/625Z,
  R1 = Z/5Z,
and let:
  red : R4 -> R1
be the natural reduction.

The temporary RMFE maps are R4-linear:
  phi4,
  psi4,
  pi4 = phi4 o psi4.

Reducing the coefficients of these linear maps modulo 5 defines:
  phi1,
  psi1,
  pi1.

For every temporary-ring element x:
  red(pi4(x))
    = red(phi4(psi4(x)))
    = phi1(psi1(red(x)))
    = pi1(red(x)).

Therefore:
  red o pi4 = pi1 o red.

The final mod-5 recode is not a new map family; it is exactly the reduction of the temporary
625-adic recode map.

## 2. Automorphism representation also reduces coefficientwise

Aung represents the temporary map as:
  pi4(x) = sum_i theta_i * sigma^{s i}(x).

The Galois-ring automorphisms preserve the ideal generated by 5 and therefore descend to the
residue-field/quotient algebra.

Hence:
  red(sigma^{s i}(x))
    = sigma_bar^{s i}(red(x)).

Reducing each public coefficient theta_i modulo 5 gives:
  pi1(x_bar)
    = sum_i theta_i_bar * sigma_bar^{s i}(x_bar).

Thus the final mod-5 Recode uses:
- the SAME automorphism exponents/schedule;
- the SAME structural linear map;
- only public constants interpreted modulo 5.

No hidden permutation or new nonlinear operation appears at the final boundary.

## 3. Why Recode is still required after the division ladder

The correction-map proof tracks the decoded RMFE vector through Algorithm 4.
Immediately before the final Recode, the current element need not lie in im(phi), but its decoded
value psi1(u) is the desired digit-extracted application tuple.

Applying:
  pi1(u) = phi1(psi1(u))

therefore re-encodes exactly that tuple into the RMFE image.

This is the role of line 10 in Algorithm 4.

Consequently the candidate must NOT omit the final Recode merely because its input started in
im(phi), and it must not move Recode before the p-adic division ladder.

## 4. HElib ptxtSpace=5 constant semantics

The final Algorithm-4 ciphertext has:
  ptxtSpace = 5.

For raw ZZX / DoubleCRT public recode constants, pinned HElib constant multiplication leaves
ptxtSpace unchanged.

Semantically, integer polynomial coefficients are interpreted modulo the current plaintext space,
so a constant originally derived over Z_625 automatically acts through its mod-5 reduction on a
ptxtSpace-5 ciphertext.

Therefore a source implementation using the same integer-polynomial constants realizes the
coefficientwise reduced recode map.

## 5. Encoded-BGV constants at ptxtSpace 625 are also type-compatible

Pinned Ctxt::multByConstant(FatEncodedPtxt_BGV) checks plaintext-space mismatch and calls:
  reducePtxtSpace(ptxt.getPtxtSpace()).

Pinned reducePtxtSpace sets:
  ptxtSpace <- gcd(current_ptxtSpace, requested_ptxtSpace).

Thus for:
  current = 5,
  encoded constant space = 625,

the result is:
  gcd(5,625) = 5.

The ciphertext remains at ptxtSpace 5.

Its intFactor is merely reduced modulo the same gcd, which is a no-op for an already-valid factor
modulo 5.

Hence even cached/reused 625-typed encoded public constants do not force a mod-5 Algorithm-4 output
back to 625.

They may have a more conservative tracked size/noise bound than freshly reduced mod-5 constants;
that is a VALUE/noise issue, not a correctness mismatch.

## 6. Existing temporary-625 key-switch matrices remain valid at ptxtSpace 5

Pinned KeySwitch documentation states:
if a ciphertext is encrypted relative to plaintext space p' and key-switched with a matrix built
relative to plaintext space p, the resulting ciphertext is valid relative to:
  gcd(p',p).

Pinned Ctxt::reLinearize implements this explicitly:
  tmp.reducePtxtSpace(W.ptxtSpace)
before applying a BGV KeySwitch matrix.

For the final Recode:
  p' = 5,
  W.ptxtSpace = 625,

so:
  gcd(5,625)=5.

Therefore:
- the ciphertext stays at plaintext space 5;
- the existing temporary-625 1D/Frobenius matrices are correctness-compatible;
- no second mod-5 evaluation-key family is needed.

This applies to either Aung Recode evaluation strategy because both use the same public
automorphisms/key-switch infrastructure.

## 7. intFactor remains well typed through final Recode

The final Recode is a linear map implemented using:
- automorphisms/relinearizations;
- public polynomial constants;
- additions.

At current ptxtSpace 5:
- automorphism preserves intFactor;
- relinearization with a 625 matrix calls reducePtxtSpace(625), which leaves ptxtSpace 5 and reduces
  intFactor modulo 5;
- public polynomial constants preserve intFactor;
- same-origin linear terms have one common factor, so additions need no branch-specific
  harmonization.

Therefore Recode does not require restoring the source application factor in advance.

## 8. Final source-factor restoration must remain AFTER Recode
