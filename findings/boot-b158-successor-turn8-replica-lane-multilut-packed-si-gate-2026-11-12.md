## Proposed concrete constructive design and scope
Plaintext ring slot count N=32768. Physical output of B175 before final aggregation is indexed by j=0..32767 and contains eight block positions per group; B175 audit independent reference has expected POINTWISE_j = B_{j mod8}(x)*y^{j mod8} for CASE1, with y=x^8192=1. For general x (as a mathematical proposed layout), set group g=floor(j/8), inner index b=j mod8. There are G=N/8=4096 distinct groups per physical 32768-slot ciphertext. Publicly assign each group g an application function label h(g) in 0..K-1.
For each function f, split public arbitrary LUT F_f(X) into eight polynomials B_{f,b}(X)=sum_{i=0}^{8191} a_{f,bH+i} X^i. Let ciphertext input X replicate the same scalar phase x across all slots. Generate/shared packed baby basis P_H(x) and group selector Y_b(x)=y^b, y=x^8192. Via a *proposed* public lane-specific coefficient table, make the LT plaintext value L_{g,b}=B_{h(g),b}(x). The existing plaintext selector mathematically satisfies G_{g,b}=Y_b(x), independent of h(g). Pointwise multiplication then yields
  W_{g,b}=B_{h(g),b}(x) * y^b.
Group-local sum over b gives
  sum_{b=0}^7 W_{g,b} = F_{h(g)}(x)
for all x in F_65537, including x=0. This is a conditional full-output plaintext identity, not a verified source typed ciphertext circuit. A per-group reduction needs carefully scheduled masked shifts/rotations; source availability, key reuse, row-crossing and final BFV-to-LWE extraction/demultiplex costs UNKNOWN. One could place function labels in different complete groups, potentially K<=4096 in the ideal layout, but 4096 is only an abstract slot-capacity bound, not a realized throughput claim.
Potential optimistic ct-ct count: one shared 21-ctct basis + one shared 4-ctct GROUPED + one shared final SI = 26 through pointwise for any K, assuming all fused public LT masks are expressible with no extra ct-ct. K separate B175 skeleton invocations cost 26K. Thus an optimistic count reduction 26K→26, *not* a demonstrated speedup: public LT masks and rotations, extra output sums, LWE extraction, key/material and memory must be included. In particular, B175 has 8 ct-pt in its final LT and 16 LT rotations per standalone run; whether diverse per-group masks retain 8 ctpt/16 rotations rather than K times these is UNVERIFIED.
An alternate idea to simply share the basis but run K independent LTs and SI final operations gives 25+K ct-ct under same input and is just common-subexpression elimination, already broad prior. The proposed new detail is fused per-group coefficient heterogeneity keeping one final multiplication.

## Decisive correctness killer gate
The candidate claims arbitrary K public LUTs and therefore must include the valid all-identical family F_0=...=F_{K-1}=F. In that specialization all lane-specific plaintext masks collapse to the original B175 public F coefficient masks. If the proposed evaluator uses the SAME B175 L18 LT8, GROUPED and final MulRelinScaleInvariant, its fused ciphertexts and their operation results are exactly B175 (for matched randomness, keys and source schedule); no change in error geometry or scale law is introduced by the labels.
B175 native audit demonstrates this exact CASE1 instance fails the terminal SI: LT8 required577,GROUPED633,pointwise664 and 32767 of 32768 decoded slots wrong. Any claimed arbitrary-function fixed-Q correctness theorem for the unchanged B175 SI circuit contradicts that verified regression. Thus the proposed packing mechanism cannot on its own repair fixed-Q B175, even though algebraic plaintext packing is valid.
This regression does NOT show every heterogeneous multi-function workload must fail or preclude a modified ciphertext evaluator having different source-level error/carry behavior. Nor does it rule out the idea as an amortization strategy AFTER a separate native-corrected bootstrap; it falsifies this precise current fixed-Q construction's status as standalone publishable fix.
Separately, the B175 output after pointwise has later expected aggregation/extraction not run. A new full multi-output algorithm needs exact source schedule for group-local sums and BFV-to-LWE output; no complete candidate correctness claim established.
