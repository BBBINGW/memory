## 1. Exact subring geometry

Let
  S = Z/625Z,
  R = S[X]/(X^16384+1).

Define
  Y = X^1024
and
  R_8 := S[Y]/(Y^16+1) embedded in R.

This is the plaintext ring of cyclotomic index m_r=32:
  phi(32)=16,
  ord_32(5)=8,
  number of slots=16/8=2.

Thus its two slots are degree-8 Galois-ring slots E_8=GR(625,8).

The outer ring has:
  phi(32768)=16384,
  ord_32768(5)=8192,
  two slots.

Hence the subring envelope preserves the same two physical slots while reducing only the intra-slot extension degree from8192 to8.

## 2. The proposed input A(c) really lies in R_8

For RMFE component i=0,...,4, tau_i(c) is an existing Aung component projection whose plaintext has scalar values
  (a_i,0, a_i,1) in the two physical slots.

For p=5=1 mod4, Geelen's subring-packing result implies scalar-packed plaintexts lie in the m'=m/d=4 subring of R. In the current outer ring this subring is generated by X^8192=(X^1024)^8=Y^8 and is contained in R_8.

Define:
  A(c) = sum_{i=0}^4 X^(1024 i) tau_i(c)
       = sum_{i=0}^4 Y^i tau_i(c).

Every term lies in R_8, hence A(c) lies in R_8.

At physical slot j, X^1024 evaluates as the corresponding primitive-32 root zeta_32,j. Therefore A(c) has slot value
  sum_{i=0}^4 a_i,j zeta_32,j^i,
which is exactly an E_8 element whose power-basis coordinates 0,...,4 contain the five RMFE scalar components and coordinates5,...,7 are zero.

So the E8 envelope is an exact subring plaintext invariant, not an analogy.

## 3. Every R_8 automorphism lifts exactly to an outer-ring automorphism

For any u in (Z/32Z)^*, choose the same odd integer u as an element of (Z/32768Z)^*.

The outer automorphism
  tau_u : X -> X^u
acts on Y=X^1024 as
  tau_u(Y)=X^(1024u)=Y^u.

Therefore the restriction of outer tau_u to R_8 is exactly the m=32 automorphism Y->Y^u.

In particular:
- subring Frobenius Y->Y^5 is the restriction of outer Frobenius X->X^5;
- its powers j=0,...,7 are the degree-8 Frobenius orbit required for E_8-linearized maps;
- the two-slot quotient action uses the same -1 representative in both m=32 and m=32768.

Thus the full automorphism vocabulary needed by the degree-8 maps exists natively in the outer ciphertext ring.

No ring-switch key is required for this algebraic interface.

## 4. Every R_8 public constant lifts exactly

For any c(Y) in R_8, use the outer plaintext constant
  c(X^1024) in R.

Multiplication by this constant preserves R_8 on R_8 plaintexts.

Pinned HElib matmul implements linear maps through sums of public-constant multipliers and automorphisms; its source describes the generic form
  sum_i sum_j c_ij sigma^j rot^i(v).

Pinned intraSlot unpack similarly computes Frobenius images of one ciphertext and combines them with public constants.

Therefore a degree-8 SlotToCoeff/CoeffToSlot or coordinate-extraction map can be implemented as a CUSTOM LIFTED OUTER-RING LINEAR MAP using the ordinary Ctxt automorphism and multByConstant machinery.

Important implementation correction:
  the candidate must NOT call stock outer ThinEvalMap or stock unpack and pretend their degree is8.
The outer EncryptedArray has degree8192. A dedicated E8 helper must precompute the degree-8 constants and invoke only the required lifted outer automorphisms.

This is a narrow implementation contract, not an algebraic obstruction.

## 5. Source-faithful SlotToCoeff interface

Geelen's fully packed p=1 mod4 transform on m_r=32 is an S-linear map on two E_8 slots, decomposable as
  M^{-1} U_2 M
(up to the paper's chosen direction/permutation convention).

Applied to A(c), it sends the two slot values with power-basis coordinates a_i,j into the 16 coefficient positions of R_8.

Under the embedding Y=X^1024, these become outer-ring positions
  X^(1024 t), t=0,...,15,
with the ten message-bearing component positions corresponding to the five coordinates in each of two slots (possibly under a fixed public coefficient permutation from the chosen transform decomposition).

No two RMFE scalar components collide.

Hence the standard bootstrapping key stage sees ordinary coefficient-domain p-adic message representatives, rather than a CRT-mixed extension value.

This is exactly the invariant needed to avoid the carry counterexample that killed the older raw slot-recode shortcut.

## 6. The one MultKey stage may leave R_8; this is expected

Pinned HElib thinReCrypt performs:
  SlotToCoeff
  -> canonicalize/mod-down/key-switch
  -> rawModSwitch
  -> newMakeDivisible
  -> divide
  -> recryptEkey * zzParts[1] + zzParts[0]
  -> CoeffToSlot.

The reconstructed noisy plaintext need not remain in the sparse subring.

Geelen 2024/153 explicitly identifies the same phenomenon for thin bootstrapping: the CoeffToSlot input after the inner product is an element of the larger ring R rather than R', and a trace R/R' is required first to remove redundant coefficients.

Therefore the candidate does NOT require the one MultKey to preserve R_8 support.

It only requires exact recovery of the desired coefficient positions before the inverse E8 map.

## 7. RM_10 is exactly the required recovery map

For R_8 embedded by Y=X^1024, the fixed subgroup is
  H={u in (Z/32768Z)^* : u=1 mod32},
with |H|=1024.

The normalized relative trace is
  P_H = 1024^{-1} sum_{h in H} tau_h,
where
  1024^{-1} mod625 = 224.

The previously persisted RM10 audit proves this is exactly the ten-stage RM_10 projector and is support-minimal in the standard automorphism-multiplier model.

On the coefficient basis:
  P_H(X^e)=X^e if 1024 divides e,
  P_H(X^e)=0 otherwise.

An independent exact monomial audit for all e=0,...,16383 agrees with this identity: the unnormalized H-trace gives 1024 X^e on multiples of1024 and zero elsewhere.

Thus after the noisy one-MultKey reconstruction, normalized RM_10:
- removes every coefficient outside the embedded R_8 support;
- preserves every intended active coefficient exactly modulo625;
- returns the plaintext representative to R_8.

This is precisely the source-shaped trace-before-CoeffToSlot pattern identified by Geelen and Ma.

## 8. Lifted inverse map and eight-coordinate unpack

Once RM_10 has returned the plaintext to R_8, apply the lifted inverse degree-8 transform.

Each resulting E_8 slot has eight S-coordinates. The outer Frobenius restricts to an order-8 Frobenius on E_8, so coordinate extraction can use the same linearized-polynomial principle as HElib unpack, but with:
  j=0,...,7
rather than the outer degree8192.

Compute eight custom E8 coordinate ciphertexts, keep coordinates0,...,4, multiply them by the fixed RMFE basis elements phi(e_i), and sum.

The result has slot value
  phi(z_0,j,...,z_4,j)
for the five coefficient-domain noisy scalar intermediates z_i,j.

No high p-adic digit extraction has been interchanged with an arbitrary CRT linear combination.

The existing Aung correction DigitExtract is therefore reached at the intended representation boundary, subject to the still-unproven quantitative noise/capacity conditions.
