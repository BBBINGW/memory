## ONE exact information sufficiency falsifier [DERIVATION]
Explicit **application-level shared-state contract** (additional stated assumption, not inferred solely from JSON schemas): App A `calendar.reserve(slot)` writes occupancy of shared slot u, and App B `rooms.book(u)` must reject any request if occupancy=1 and succeed if occupancy=0. The user task description, B API definition, B local call/response history, B current call `rooms.book(u)`, time/user/public context are identical in two hypothetical worlds W0 and W1. In W0 A has not written occupancy(u), in W1 A has successfully reserved u; this one A write is NOT supplied to B. Both worlds are consistent with B's identical local observation I_B but the required correct responses differ:
 I_B(W0)=I_B(W1) ; r*(W0)=SUCCESS, r*(W1)=CONFLICT.
Hence any deterministic B-local policy f(I_B) must make the same output in both and fail one; any randomized one with output success probability z has errors (1-z) and z in the two worlds, so worst-case success<=max_z min(z,1-z)=1/2 if required binary outputs and worlds adversarially chosen. This is an information indistinguishability witness, NOT statistical assessment of LLM simulation. The contract could be represented by a shared calendar inventory, cross-app workflow, or common resource: if two apps do NOT actually share state, the witness does not apply.
A cross-app *causally sufficient information* interface needs to expose at least an occupancy event or derived current availability for u to B. However this is a NECESSARY INFORMATION requirement, not evidence a NEW primitive is needed. Typical ways to resolve include global state manager, event log, executable shared backend, a dependency graph plus read-your-writes/invalidation, or compact per-request causal evidence. These are generic distributed systems/data provenance methods and partially existing in Gaia2/StateGen/AWM. A simple 'send all A history' also fixes this toy at unknown LLM context cost, and no original optimization bound has been proved.
