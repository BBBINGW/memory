## ONE primary hypothesis and cheapest decisive test
[HYPOTHESIS, FALSIFIED FOR LITERAL ALGORITHM] Given B naturally indexed RLWE samples with constant plaintexts m0,...,m(B−1), Algorithm5 as printed produces the claimed order-preserving packed plaintext for all powers-of-2 B|N, 2≤B≤N.
[FALSIFIER] One exact zero-noise input vector in the negacyclic ring where the *literal* tree automorphisms, trace-to-K_(N/B), and temp multiply fail to match `Σ_j m_j X^(jN/B)temp(X)`.

## SOURCE-COMPATIBLE EXACT DERIVATION
In `R_Q=Z_Q[X]/(X^N+1)`, choose Q odd with inverses of powers of two and ignore all ciphertext noise. For one-hot basis input `m_j=1` and remaining inputs0:
- at each combine level i, the digit corresponding to input INDEX j modulo 2^i is positioned by exponent `N/2^i`; after k=log2B stages, the result BEFORE trace is
`P_pre(X)=X^((N/B) bitrev_k(j))`,
where `bitrev_k` reverses the k-bit binary expansion of j. This derives from the specific left-to-right pair merge and requires no cryptographic assumption. For generic inputs linearity gives `Σ_j m_j X^((N/B) bitrev_k(j))`, not `Σ_j m_j X^(jN/B)`.
- The B desired locations `X^((N/B)j)` span **K_B** (subring generated by X^(N/B)), whereas printed trace target is `K_(N/B)` (generated by X^B). If B²>N, the printed trace K_(N/B) has dimension N/B<B, so it CANNOT preserve all B independent target plaintext degrees of freedom. Even when B²≤N and trace preserves these locations, it does not cure bit reversal.
- A simple algebraic **candidate correction** for literal Algorithm5 is to pre-permute the B input ciphertexts by `bitrev_k` AND trace into `K_B`. This makes the pure constant-input packing identity exact, while its effect on all nonconstant ciphertext noise or actual output correctness still needs checking.

## ONE exact linear-basis test [PASS FALSIFIER]
A Python Fraction-based, negacyclic X^N+1 implementation takes all B one-hot plaintext inputs for each tested (N,B). Uses exact exponent shifts and automorphisms (no RLWE noise), normalized trace as a field projection, then multiply by source temp. For every configuration compare all B basis vectors to the stated order-preserving packed block vector:
`N=16 B=4`: literal Algorithm5 **2/4**; with bitreversed input **4/4** (both K_(N/B)=K_B=K4).
`N=16 B=8`: literal **1/8**; bitreverse alone **2/8**; bitreverse+trace K_B **8/8**.
`N=32 B=4`: literal **2/4**; bitreverse **4/4**; trace-to-K_B+bitreverse **4/4**.
`N=32 B=8`: literal **2/8**; bitreverse only **4/8**; bitreverse+K_B **8/8**.
`N=1024 B=16`: literal **4/16**; bitreverse alone **16/16**; bitreverse+K_B **16/16**.
N1024 B16 satisfies `log2N=10<B=16<N`, which is consistent even with the paper's Table1 parameter prose. Only bit-reversal palindromic indices happen to match natural expected output on 4/16 one-hot tests. For an isolated natural input j1 the pretrace output is X^512, although source target is X^64.

**Concrete** N16 B4, input (0,1,0,0): intended `X^4(1+X+X²+X³)`, literal source gives `X^8(1+X+X²+X³)`. No noise, rounding or halfinteger ambiguity.
**Concrete trace issue** N16 B8, one-hot input j4: pretrace X²; trace to K_(N/B)=K2 deletes it; the output is zero, whereas the intended packing contains one populated block. Trace K_B=K8 preserves it (but alone not correct slot order).

The basis tests are sufficient for ALL constant-valued B input vectors by linearity of the noiseless mapping; they DO NOT prove a full FHE algorithm correct for arbitrary RLWE noise or automorphism key switching, or locate any code-level bug.
