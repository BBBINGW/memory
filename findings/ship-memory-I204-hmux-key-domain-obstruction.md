ONE PRIMARY HYPOTHESIS (H204): From `sum_d beta_d=1`, one can remove a complete GGLWE HMux key per digit group via direct public affine/coefficientwise combination of existing raw/prepared key rows under a **single unchanged output key domain**, with no additional per-term Galois alignment or encrypted-control computation.

ONE FALSIFIER AND EXACT EXECUTED TEST: Choose a source-valid standard plan `N=16,h=2,window=3,theta=1,mux_base=2`, so first digit choices have rotations 0,1 and either one-hot state is legal. Standard `R=Z[X]/(X^16+1)`, dense coefficient secret `s=X`. Source `g_0=5^8 mod32=1`, `g_1=5^7 mod32=13` and inverses `1,5`, hence candidate output keys `sout0=X` and `sout1=X^5`. For legal beta=(1,0), an input rank2 first-column gadget row encrypts messages t0=X and t1=0 (common gadget factor omitted without affecting mismatch). Under decryption convention Dec_(sout)(b,a)=b+a*sout, choose noiseless valid rows `c0=(0,1)`, `c1=(-X^5,1)`. Each decrypts to intended t_d under its **own** output key. But componentwise sum c0+c1=(-X^5,2) decrypts under sout0 to 2X-X^5 (not X), residual X-X^5, and under sout1 to X^5 (not X), residual X^5-X. Both residuals nonzero exactly. Thus no unconditional direct raw-row sum identity under either key. This is NOT a full probabilistic FHE evaluation-key sampler and NOT a lower bound against alternative compressed representation or extra processing.

[DERIVED] Even after publicly automorphizing each individual row to align destination secret s, its first input column plaintext is beta_d*sigma_(g_d)(s), whose one-hot sum depends on *which d was secretly selected*; unlike its second-column sum=1, it is not a fixed public encryptable constant. The original evaluator requires per-candidate Galois alignment. This single source/domain obstruction prevents treating all raw GGLWE rows as already in a shared key domain; it does not rule out more elaborate key sharing.
