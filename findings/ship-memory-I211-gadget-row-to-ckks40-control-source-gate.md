## [DERIVED] Exact source-limb identity

Notation: (B=52), original GGLWE at physical `k_key=676` and 13 limbs; each `VecZnx` limb `j` represents coefficient weight `2^{-Bj}`, as documented by source decode. HMux second input col encrypts β constant polynomial; row index `i=10` embeds β in limb10, i.e. source plaintext `β·2^{-520}` in fractional torus notation. Its ciphertext decrypts under `t_g=σ_(g^{-1})(s)` to this value + error, with a physical bottom guard limb.

`σ_g` publicly converts cipher destination key to dense `s`, since β is constant:
`Dec_s(σ_g(C)) = β·2^{-520} + σ_g(e)`.

A desired CKKS **k624** scale `Δ=2^40` constant plaintext is encoded in last limb11 (there are 12 limbs), so its **fractional torus value** is `β·2^40·2^{-572}=β·2^{-532}`. Thus multiply by public `2^{-12}`:
`2^{-12} * (β·2^{-520}) = β·2^{-532}`.

**Proposed public operation:** for BOTH transformed GLWE components, apply `module.vec_znx_normalize(...,res_base2k=52,res_k=624,res_offset=-12,...)` from 13-limb source to 12-limb destination and stamp target `log_delta=40, log_budget=584, complex slots`. This should produce a CKKS-capable **uniform slot** β ciphertext (constant plaintext polynomial, because CKKS Eval of constant polynomial yields identical slots), not a β row in only one slot. No secret-dependent operation; no extra ciphertext multiplication. Source `ckks_prepare_right` can in principle prepare it, but no implemented adapter has been compiled.

**Integer view:** 13-limb source has denominator `2^(12*52)=2^624` for its fractional torus representation. Row10 β is integer `β*2^(624-520)=β2^104`; at 12-limb output the denominator is `2^(11*52)=2^572`. Multiplying physical torus source by `2^-12`, then rounding to output grid, is exactly *coefficientwise nearest-integer division by* `2^(624+12-572)=2^64`. The β plaintext becomes `2^(104-64)=2^40`, the standard source CKKS representation.

**Noise/rounding:** a source encryption error residing in guard limb12, if its integer size is e, is `e 2^-624` source; after public -12 offset, it is `e2^-636`. Output 12-limb low-grid quantum is `2^-572`; for small |e|<2^63, direct error is below half-grid quantum. HOWEVER real operation rounds ciphertext components **separately**, so decryption receives extra terms bounded by mask-component rounding times `||s||_1`. An ideal ciphertext-message-only rounding argument would be insufficient. Also the noise from real IFMA transforms, FFT errors, normalization, subsequent 480 high precision ct×ct gates and actual public security are all still unverified.
