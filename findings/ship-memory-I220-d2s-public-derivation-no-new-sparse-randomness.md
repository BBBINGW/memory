## Source-level falsifier [DERIVATION from inspected code]

Let published D2S key be K and an arbitrary canonical input rank1 dense ciphertext be c=(b,a) at q0=2^52. The pinned algorithm applies a deterministic GGLWE product to **only the input mask a**, followed by digit/DFT/normalization. Write output schematically in the repo's `Dec_t(b',a')=b'+a't` sign convention:
  KS_K(b,a) = ( Norm_body( Product_body(a,K) + b ), Norm_mask( Product_mask(a,K) ) ).
Define F_K(a)=Norm_mask(Product_mask(a,K)). **F_K depends on K and a, but never on b, m, fresh errors, or an RNG called within KeySwitch.** Take one dense input c=(b,a), choose arbitrary public plaintext offset δ, and form c_delta=(b+δ,a). Both are valid encryptions of publicly related messages with the SAME dense encryption randomness/noise. Source-controlled KeySwitch outputs satisfy
  mask(KS_K(c_delta)) = F_K(a) = mask(KS_K(c))
**exactly**, even though their known plaintexts differ. This directly falsifies the blanket claim that replays or public plaintext modifications generate fresh, independently uniform sparse masks. Their bodies differ by δ up to canonical normalization/rounding; mask identity requires no ideal-noise approximation.

The error after switching has schematic form e_out = e_dense + gadget-action_a(e_K) + e_normalize. The term e_K is the **single fixed key-generation noise polynomial** reused across outputs, and normalization is deterministic; it is not an independently sampled sparse-secret Gaussian per query. A fresh `Enc_pk` call can generate a new e_dense and a new input mask a; accordingly different output masks MAY vary and could even have desirable marginal/conditional distributions. **No universal non-independence theorem for fresh independent PK encryptions is proven here**, and a secret distribution / linearization / output error-convolution estimator remains OPEN.

## Stronger exact adversarial transcript simulation [DERIVATION]

In the explicitly PK-enabled game, give simulator/public adversary the same public bundle (pk_s,K) and public algorithms. For any chosen-message query m, the simulator runs `ct_s=Enc_pk_s(m;fresh public coins)` and then deterministic `ct_t=KS_K(ct_s)` using K. Its outputs have the **same distribution** as the interface that merely does those two public operations. Replaying it adaptively to any number of queries needs no hidden secret or additional oracle. Thus publishing or locally calculating these **publicly derivable** ciphertexts does not supply *extra secret-dependent information beyond the existing pk_s,K*. This is a data-processing / exact-simulation fact, **NOT** a proof that such transforms are useless to an attack. An algorithm might exploit public restructuring or correlated relations for a faster attack; a simulator can perform that attack's same steps on the base public bundle.

Important distinction: the structural identity `same input a => same output sparse mask` witnesses that **a naive collection including duplicated/replayed masks is not i.i.d.**; it does **not by itself disprove** a properly modeled collection of fresh randomized dense PK encryptions may induce an independent (conditional on keys) output mask distribution. It also does not rule out explicitly provided sparse public keys or a genuine sparse-key encryption oracle, neither of which is generated in the bare ShipKeySet.
