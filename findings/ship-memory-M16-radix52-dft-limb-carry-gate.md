## Derived corrected mixed-DFT arithmetic [DERIVATION]

Use radix R=2^52 and full `VecZnxBig` signed coefficient-limb value `V(L) = Σ_{j>=0} L_j R^{-(j+1)}`, ignoring final torus canonical rounding. For first GGLWE branch raw G=(G_0,...,G_9), original offset0 gives `V(G)`. For second β-body ordinary convolution raw H=(H_0,...,H_17), original offset−52 gives `R^-1 V(H)`. We need their sum for each candidate, each of two output GLWE components:
```
  desired = σ_g[V(G) + R^-1 V(H)].
```
**Correct no-multiply accumulator with common normalization offset0**:
```
  T_0 = G_0
  T_j = (j<10 ? G_j : 0) + (1<=j<=18 ? H_{j-1} : 0)  for j=1,...,18,
  V(T) = V(G)+R^-1 V(H).
```
Apply same public per-candidate σ_g to both source branches, and accumulate at matching limb indices across candidates; then perform ONE IDFT+big normalize at offset0. This preserves exact pre-rounding real torus-phase algebra. Since sources are signed residues in each CRT plane, relocating whole packed limb planes is only memory movement, no ×2^52 multiplications; coefficient carries are resolved by the existing final `I128NormalizePlan` if DFT CRT coefficients remain in range.

**Bounded IFMA CRT sanity check (NOT a full production proof):** Suppose every input radix limb is centered |a_i|,|b_i| <2^51, N=16384, and a GGLWE or helper polynomial output limb has at most 9 limb-pair convolutions. Each output coefficient bound <N*9*2^102, exponent <2^119.17. Under a four-candidate mux group, combining at most one first branch and one second branch per candidate at a shifted position contributes <4*2*N*9*2^102, with exponent <2^122.17 < signed half-CRT ~2^125. Additional backend accumulators/mixed precision, digit size, actual bounds and CRT aliasing must be reviewed on implementation. No claim for arbitrary tensors or wider radix limbs.

**Failure of M15 alternative multiply-in-CRT approach:** Let every dense radix limb a_i = 2^51−1, b_0=2^51−1 and b_i=−(2^51−1) for i>0 in degree N=16384 negacyclic ring. This is a legal centered signed 52-bit limb pair. Their convolution constant coefficient = `N*(2^51−1)^2` (~116 bits), which fits signed CRT. Multiplying the resulting single-limb CRT value by `R=2^52` makes the underlying desired integer ~168 bits and must wrap modulo the ~126-bit CRT modulus. Recovering after IDFT returns the wrong signed integer. It is **not safe** to represent the radix shift as multiplying a raw DFT residue limb by 2^52, even though abstract torus phases admit that identity. Shift the HELPER limb location instead.

**Boundary carries are essential:** For target k428, normalized output quantization step is `2^-428`, and limb 8 represents weight `2^-468`. Put a GGLWE coefficient at limb8 equal to `2^39−1` and one shifted helper contribution at the same index equal to 2. Each individually falls below the half-ULP rounding threshold and rounds to zero; their sum is `2^39+1`, exceeds half and rounds to one output ULP. Thus doing one **combined** normalization and retaining the guard digit is necessary; naive separately round then sum loses 1 ULP. This is a mathematical rounding counterexample, not a real IFMA divergence claim.
