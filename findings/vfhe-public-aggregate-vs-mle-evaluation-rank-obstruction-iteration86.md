## One primary hypothesis and minimal test
[HYPOTHESIS — FAIL] For an arbitrary postcommit Boolean challenge mask alpha on the digits of one `h~` oracle, the original succinct verifier can directly use ONE ordinary native PCS opening `h~(r)` (possibly times a publicly chosen scalar) as a substitute for the **exact integer** `A=Σ_i alpha_i h_i`, without reconstructing digits or adding a new aggregation argument.
[FALSIFIER] A Boolean alpha whose coefficient tensor cannot equal any single MLE point-evaluation weight tensor even over one native finite field.
[TEST] One 2-variable (4-digit) tensor-rank check, plus exact finite-field sanity calculation. This directly kills the single-opening shortcut; does not attempt a universal lower bound on specially designed proof protocols.

## Exact rank obstruction
Let Boolean indexed vector h=(h_00,h_01,h_10,h_11) with MLE
  `h~(r,s)=(1−r)(1−s)h_00 + (1−r)s h_01 + r(1−s)h_10 + rs h_11`.
The coefficient matrix of this **single evaluation** is
  `W(r,s) = [[(1−r)(1−s),(1−r)s],[r(1−s),rs]] = [1−r,r]^T [1−s,s]`,
hence rank(W)≤1 over any field (and det(W)=0). Multiplying the opening by a scalar preserves rank≤1.
Choose legal Boolean alpha=(1,0,0,1), i.e. matrix
  `M_alpha=[[1,0],[0,1]]`.
Then det(M_alpha)=1, rank(M_alpha)=2 in every characteristic, so **no** single MLE evaluation (even publicly scaled) equals the alpha-weighted inner product **for all possible h**.
Purely algebraic corollary in the **DIRECT LINEAR COMBINATION OF POINT-OPENINGS MODEL**: a sum of k MLE openings with public scalar weights has 2-way-flattened matrix rank ≤k. Any alpha of flattening rank t needs ≥t openings. E.g. a 32×32 identity Boolean alpha needs ≥32 such direct openings, so the q=25 figure quoted for the *entire* original Pi_range cannot be read as a pre-existing guarantee that its fixed collection of evaluation results can recover every such alpha aggregate. **NOT** a universal lower bound on sumcheck, nonlinear proofs, new PCS APIs, or verifier time. Evaluation locations/challenges in actual source are protocol-specific; this toy does not model the complete source query transcript.

## Exact missing interface / significance
[DERIVED] A canonical/relaxed remainder might be uniquely determined **conditional on fixed complete** c',c'' (I85), but the verifier does not directly possess the full c' coefficient array and h from original public statement. The existing native PCS opening only authenticates point evaluations of `h~` (plus protocol-specific linear combinations). It cannot be reinterpreted as an *arbitrary* postcommit Boolean-mask exact **integer** aggregate by a free type conversion. This is a source-backed *direct-reuse obstruction*, distinct from the I80 cross-characteristic DualPCS interface and I82 masked Brakedown failure, and consistent with I78 postchallenge CRT patching.
[OPEN] Whether a **separate sumcheck or specially structured public mask** can authenticate an exact aggregate in near-original verification cost remains open. A native field sumcheck only certifies modular equality unless exact global integer range/lifting and witness binding are additionally proved. No performance bound or novel primitive established; no full soundness/privacy repair.
[RESEARCH VALUE] More precise rejection criterion: don't propose "one more h~(r) opening certifies arbitrary integer A"; require a verified aggregate-claim protocol, explicit pre-challenge binding, native ring/CRT lift, and a cost model. This avoids an otherwise attractive but false shortcut.
