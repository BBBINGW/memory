## FACT: source F.2 transmits m_B field elements and opens encoded columns
§5 p25 describes polynomial coefficient table as an m_B×m_B matrix for even number of Boolean variables; Appendix F.2 p51 **explicitly transmits** v'=q1 U_f, length m_B, per FIELD component in each evaluation phase. It also sends sampled Merkle-authenticated encoded columns, each carrying m_B field elements plus Merkle proof. F.2 explicitly permits reusing the **testing phase** for multiple evaluations on the SAME commitment, not the evaluation phase at distinct points. F.1 p50 defines ONE ring PCS evaluation as execution of all μ field PCS evaluations. This is not one scalar proof, and doesn't claim a general compressed cross-field protocol.

§3.1 p10 defines q0=product_(i=0)^L p_i and each p_i yields N/d fields; literal μ=(L+1)N/d=8192 for L3,N8192,d4. But §6.2 p29 writes 'LN/d components', which gives μ=6144. Treat this as **SOURCE NOTATION AMBIGUITY** (possibly off-by-one convention), NOT a verified correctness flaw. Use both μ options and do not silently settle it. Every native F_(p_i^4) has cardinality at least 2^192 for 49-bit primes (p_i>2^48).

## Exceptional-set entropy and honest CRT work
§3.1 p11 says maximum exceptional-set cardinality = smallest field cardinality, i.e., |S|max = min_i p_i^4, at least 2^192 when each p_i has 49 bits. Definition2.1 requires distinct sampled ring elements have UNIT differences in every CRT factor. A concrete possible common indexing is 4-tuples (a0,a1,a2,a3) of integers in [0,pmin), mapped into each extension field via a fixed polynomial basis; distinct tuples differ nontrivially in every extension component, hence pairwise unit differences. Actual computational implementation/basis reconciliation untested.
At size |S|≥2^192, ideal batching random-combination error ≤2^-192 (I91), and degree-2 sumcheck on 19 variables error ≤38·2^-192 ≈2^-186.75; sum ≤39·2^-192 ≈2^-186.715, before original lookup, PCS and Fiat–Shamir. By contrast, **using only base-prime scalar challenges** gives |S|≤pmin<2^49, and the source's sumcheck guarantee 38/|S| could be as weak as ~2^-43. The high-entropy extension-field challenge is essential to invoke the advertised 128-bit-level theorem.
Crucial verifier cost: if r=(r1,...,r_ell) sampled in this large S, its projections differ across μ extension fields, so evaluating the public rank-one Boolean-mask MLE at r is GENERALLY a componentwise operation. I91 counted t_mask*(512+1024)=474,624 **ring scalar** operation units. An unfused CRT implementation does about μ*474624 ~2,916,089,856 (μ6144) to 3,888,119,808 (μ8192) field-component operation units, BEFORE source F.2 PCS verification and sumcheck work. This is a direct per-component arithmetic cost of the naive evaluation, NOT a cryptographic lower bound or an elapsed-time measurement. Efficient preprocessing or special masks might change it.

## Soundness budget: t_mask309 is not a 128-bit *total* theorem
Tight I87 mask miss ≤(3/4)^t. At t=309 it is 2^-128.2466, leaving very little budget for ANY additive other error; original source range and PCS are not proved to fit the remaining ~0.17×2^-128. A conservative mask-only sub-budget of 2^-136 needs t=ceil(136/log2(4/3))=328 masks. At t=328 the public mask-description length becomes 503,808 bits =62,976 bytes, ~61.5 KiB, and naive ring mask evaluation 328*1536=503,808 operation units.
To give ALL μ≤8192 components together ≤2^-136 PCS error by naive union bound, each must have error ≤2^-149 (assuming one additional proof per factor and no extra testing/lookup errors). Whether original Brakedown can use a suitable column-sample count is an independent analysis; the paper's 1020-column illustrative number targets **different** N,ell and should NOT be transplanted. Original soundness and privacy losses must be budgeted separately; **328 masks alone still do not certify complete 128-bit security**.
